Commands for reading file content, counting statistics, transforming text, and splitting files into pieces.

Except for `rev`, which takes only file names, they follow the GNU coreutils option grammar: bundled short flags (`-qn2`), long options and unambiguous abbreviations (`--lines=5`, `--li=5`), options after operands, and `--` to end options. `cat`, `head`, `tail`, `wc`, and `split` read standard input for a `-` operand. An unknown option or a bad number prints GNU's message and exits 1; a valid GNU option that ps-bash does not implement is refused with exit 2 instead of being ignored.

<Aside type="note">
**Records are not lines.** A pipeline record that ends mid-line (`printf a`, `echo -n`, a file with no final newline) is joined with the next record before a line-reading command sees it, so `{ printf a; printf 'b\n'; } | rev` reads one line, `ab`. Empty lines, including trailing ones, are kept: `printf 'a\n\n\n' | head` writes the same four bytes back. A missing final newline is copied through.
</Aside>

## cat

Concatenate files and pipeline input. Without flags, `cat` passes pipeline objects through unchanged and emits file lines as `PsBash.TextOutput`. With a formatting flag, every line becomes a `PsBash.CatLine`.

### Syntax

```text
cat [OPTION]... [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-n`, `--number` | Number all output lines |
| `-b`, `--number-nonblank` | Number non-blank lines (overrides `-n`) |
| `-s`, `--squeeze-blank` | Squeeze runs of blank lines into one |
| `-E`, `--show-ends` | Show `$` at the end of each line |
| `-T`, `--show-tabs` | Show tabs as `^I` |
| `-v`, `--show-nonprinting` | Show control bytes as `^X` (DEL as `^?`) and bytes 128 and above as `M-X` |
| `-A`, `--show-all` | Same as `-vET` |
| `-e` | Same as `-vE` |
| `-t` | Same as `-vT` |
| `-u` | Ignored, as in GNU |

Operands are written in argument order, so `cat head.txt - tail.txt` puts the pipeline between the two files.

### Byte handling

- A text file operand is read CRLF- and BOM-transparently: `cat crlf.txt | wc -c` is one byte short per CR. A `< file` redirect is read exactly. The same policy applies to every line tool on this page.
- A file with a NUL byte in its first 8 KB is treated as binary and copied byte for byte, so `cat image.png > copy.png` produces an identical file.
- With `-v`, `-A`, `-e`, or `-t` the file is read byte-exactly, so a carriage return shows as `^M`.

### Return type

- **No flags**: pipeline objects pass through; file lines are `PsBash.TextOutput`.
- **Any formatting flag**: `PsBash.CatLine` with these properties:

| Property | Type | Description |
|----------|------|-------------|
| `LineNumber` | int | Line number in the output |
| `Content` | string | Raw line content |
| `FileName` | string | Source file path (empty for pipeline input) |
| `BashText` | string | Formatted line, including the number and markers |

### Examples

```bash
printf 'alpha\n\tbeta\n\n\ngamma\n' > notes.txt
cat -n notes.txt
```

```text
     1	alpha
     2		beta
     3
     4
     5	gamma
```

```bash
cat -sb notes.txt      # squeeze blanks, number non-blank lines
```

```text
     1	alpha
     2		beta

     3	gamma
```

```bash
printf 'a\tb\r\n' | cat -A
```

```text
a^Ib^M$
```

```powershell
# CatLine properties (any formatting flag)
$lines = cat -n notes.txt
$lines[0].Content      # alpha
$lines[0].LineNumber   # 1
```

## head

Output the first part of files. On pipeline input `head` is a **pipeline bridge**: it passes the original typed objects through unchanged.

### Syntax

```text
head [OPTION]... [FILE]...
head -NUM [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-n N`, `--lines=N` | First N lines (default 10). `-n -K` prints all but the last K lines |
| `-c N`, `--bytes=N` | First N bytes. `-c -K` prints all but the last K bytes |
| `-q`, `--quiet`, `--silent` | Never print `==> FILE <==` headers |
| `-v`, `--verbose` | Always print headers |
| `-z`, `--zero-terminated` | Records end in NUL instead of newline |
| `-NUM` | Obsolete form of `-n NUM` (first argument only; `-5q` and `-2k` are accepted) |

N accepts GNU size suffixes (`1K`, `1MB`, `2KiB`). The last of `-c`/`-n` wins. With two or more files, headers are printed by default and a blank line separates the files.

On a pipe, `head -c N` stops the upstream command after the Nth byte, so `yes | head -c 5` ends.

### Return type

- **File mode**: `PsBash.CatLine` objects
- **Pipeline mode**: whatever type it receives

<Aside type="tip">
`head` preserves the type of its input. `ls -la | head -5` returns `LsEntry` objects and `ps aux | head -5` returns `PsEntry` objects.
</Aside>

### Differences from GNU

- A bare number as the first argument is taken as the count (`head 5`). GNU would read a file named `5`.

### Examples

```bash
printf '1\n2\n3\n4\n5\n' | head -n -2
```

```text
1
2
3
```

```bash
printf 'a\nb\n' > a.txt; printf 'c\nd\n' > b.txt
head -n 1 a.txt b.txt
```

```text
==> a.txt <==
a

==> b.txt <==
c
```

```powershell
# Pipeline bridge: LsEntry objects, not strings
$top5 = ls -la | sort -k5 -rn | head -n 5
$top5[0].SizeBytes    # integer
$top5[0].Name         # string
```

## tail

Output the last part of files. Like `head`, `tail` is a **pipeline bridge** that preserves the original object types.

### Syntax

```text
tail [OPTION]... [FILE]...
tail -NUM | +NUM [FILE]
```

### Flags

| Flag | Description |
|------|-------------|
| `-n N`, `--lines=N` | Last N lines (default 10). `+N` starts at line N |
| `-c N`, `--bytes=N` | Last N bytes. `+N` starts at byte N |
| `-f`, `--follow[=name\|descriptor]` | Keep reading as the file grows |
| `-F` | Same as `--follow=name --retry` |
| `--retry` | Keep trying to open a file that is missing or inaccessible |
| `--pid=PID` | With `-f`, stop when process PID exits |
| `-s N`, `--sleep-interval=N` | Seconds between polls with `-f` |
| `--max-unchanged-stats=N` | Validated only; the replacement check runs on every poll |
| `-q`, `--quiet`, `--silent` | Never print headers |
| `-v`, `--verbose` | Always print headers |
| `-z`, `--zero-terminated` | Records end in NUL instead of newline |

Numbers use the same rules as `head`. The obsolete `-NUM` / `+NUM` forms (with optional `b`, `c`, `l`, `f` letters) are honored only when the rest of the command line leaves no ambiguity (at most one file); otherwise tail reports `option used in invalid context`, as GNU does.

When following, tail prints GNU's notices: `has become inaccessible`, `has appeared;  following new file`, `has been replaced`, `file truncated`. Descriptor mode follows by path.

### Return type

- **File mode**: `PsBash.CatLine` objects
- **Pipeline mode**: whatever type it receives

### Examples

```bash
printf '1\n2\n3\n4\n5\n' | tail -n +3
```

```text
3
4
5
```

```bash
printf 'abcdefgh\n' | tail -c 4     # the last 4 bytes include the newline
```

```text
fgh
```

```bash
tail -F app.log      # follow by name, survives log rotation
```

## tac

Print lines in reverse order.

### Syntax

```text
tac [-s SEP] [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-s SEP`, `--separator=SEP` | Split records on SEP instead of newline |

`-b`/`--before` and `-r`/`--regex` are refused (exit 2).

With `-s SEP`, each record keeps the separator that ends it, as in GNU: `printf 'a,b,c,' | tac -s ,` prints `c,b,a,`. No newline is added.

### Return type

Pipeline input: the original records, in reverse order. File input: `PsBash.TextOutput`.

### Examples

```bash
printf '1\n2\n3\n' | tac
```

```text
3
2
1
```

## wc

Count lines, words, characters, and bytes. Returns `PsBash.WcResult` objects with integer properties.

### Syntax

```text
wc [OPTION]... [FILE]...
wc [OPTION]... --files0-from=F
```

### Flags

| Flag | Description |
|------|-------------|
| `-l`, `--lines` | Newline count |
| `-w`, `--words` | Word count |
| `-c`, `--bytes` | Byte count |
| `-m`, `--chars` | Character count |
| `-L`, `--max-line-length` | Width of the longest line |
| `--total=WHEN` | Total line: `auto` (default), `always`, `only`, `never` |
| `--files0-from=F` | Read NUL-separated file names from F (`-` for stdin) |

With no flags, wc prints lines, words, and bytes.

`wc` counts the byte stream, not records: `printf abc | wc -c` is `3` and `printf abc | wc -l` is `0`. The byte count of a file is its exact size, BOM included. Invalid UTF-8 bytes count in `-c` only, following GNU's UTF-8 locale rules.

Columns are laid out as in GNU. One input with one count prints the bare number (`wc -l f.txt`, `seq 3 | wc -l`). Otherwise every column is padded to the digit width of the files' total size, and to at least 7 when an input is not a regular file, such as a pipe: `echo hi | wc` prints `      1       1       3`.

A `-` operand (`wc - f.txt`) counts standard input as it streams, so endless input is not held in memory. A second `-` counts zeros, as in GNU.

### Return type

`PsBash.WcResult` with these properties:

| Property | Type | Description |
|----------|------|-------------|
| `Lines` | int | Newline count |
| `Words` | int | Word count |
| `Bytes` | int | Byte count |
| `Chars` | int | Character count |
| `MaxLineLength` | int | Longest line width |
| `FileName` | string | Source file path |
| `BashText` | string | Formatted count line |

### Examples

```bash
printf 'one two\nthree\n' > f.txt
wc f.txt
```

```text
 2  3 14 f.txt
```

```bash
wc -l a.txt f.txt
```

```text
 2 a.txt
 2 f.txt
 4 total
```

```powershell
# Typed properties
$stats = wc f.txt
$stats.Lines    # 2
$stats.Words    # 3
$stats.Bytes    # 14
```

## nl

Number lines. By default only non-empty lines get a number.

### Syntax

```text
nl [OPTION]... [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-b STYLE`, `--body-numbering=STYLE` | `a` all lines, `t` non-empty lines (default), `n` none |
| `-n FORMAT`, `--number-format=FORMAT` | `ln` left-aligned, `rn` right-aligned (default), `rz` right-aligned with zeros |
| `-s SEP`, `--number-separator=SEP` | Text after the number (default tab) |
| `-w N`, `--number-width=N` | Number width (default 6) |
| `-v N`, `--starting-line-number=N` | First number (default 1) |
| `-i N`, `--line-increment=N` | Step between numbers (default 1) |

A bad style, format, or number exits 1. Not implemented, refused with exit 2: `-b pREGEX`, and the logical-page options `-d`, `-f`, `-h`, `-l`, `-p`.

A line that gets no number (an empty line under the default `-b t`) starts with blanks as wide as the number and the separator, as in GNU.

### Return type

`PsBash.TextOutput`

### Examples

```bash
printf 'one\n\ntwo\n' | nl -b a -n rz -w 3 -s ': '
```

```text
001: one
002:
003: two
```

## strings

Print runs of printable characters found in files or pipeline input.

### Syntax

```text
strings [-n N] [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-n N`, `--bytes=N`, `-N` | Minimum run length (default 4) |
| `-a`, `--all` | Accepted; the whole input is always scanned |

`-n 0` or a non-number exits 1. Not implemented, refused with exit 2: `-d`, `-f`, `-t`, `-o`, `-w`, `-e`, `-T`, `-s`, `-U` and their long forms.

### Differences from GNU

- Printable means ASCII space through `~`. Tab is not printable, and a non-ASCII character ends a run.

### Return type

`PsBash.TextOutput`

### Examples

```bash
printf 'ab\001\002hello\000world!!\n' | strings
```

```text
hello
world!!
```

## fold

Wrap input lines to a fixed width.

### Syntax

```text
fold [-bs] [-w WIDTH] [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-w N`, `--width=N`, `-N` | Maximum line width (default 80) |
| `-s`, `--spaces` | Break after the last space in the window instead of mid-word |
| `-b`, `--bytes` | Accepted; ps-bash counts characters, the same as bytes for ASCII |

The width must be a positive decimal number; `-w 0` and `-w x` exit 1.

### Return type

`PsBash.TextOutput`

### Examples

```bash
echo 'the quick brown fox jumps' | fold -w 10
```

```text
the quick
brown fox
jumps
```

## expand

Convert tabs to spaces.

### Syntax

```text
expand [-i] [-t LIST] [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-t N`, `--tabs=N` | Tab stops every N columns (default 8) |
| `-t LIST` | Explicit ascending stops, separated by commas or blanks. The last element may be `/N` (then a stop at every multiple of N) or `+N` (then a stop every N columns after the last explicit stop) |
| `-i`, `--initial` | Convert only leading tabs |
| `-N` | Obsolete form of `-t N` |

Several `-t` options are concatenated. Past the last plain stop, a tab becomes one space. A bad list exits 1.

### Return type

`PsBash.TextOutput`

### Examples

```bash
printf 'a\tb\tc\n' | expand -t 2,6
```

```text
a b   c
```

## unexpand

Convert runs of spaces to tabs.

### Syntax

```text
unexpand [-a] [--first-only] [-t LIST] [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-a`, `--all` | Convert every run of spaces, not only leading ones |
| `--first-only` | Convert only leading spaces (overrides `-a` and `-t` in any order) |
| `-t N`, `-t LIST`, `--tabs=` | Tab stops, as for `expand`. Implies `-a` |
| `-N` | Obsolete tab width; does not imply `-a` |

### Return type

`PsBash.TextOutput`

### Examples

```bash
printf '    x   y\n' | unexpand -t 4 | cat -A
```

```text
^Ix^Iy$
```

## split

Split a file (or the pipeline) into pieces. Output files are written to the current directory; output names follow GNU coreutils 9.4.

### Syntax

```text
split [OPTION]... [FILE [PREFIX]]
```

### Flags

| Flag | Description |
|------|-------------|
| `-l N`, `--lines=N` | N lines per file (default 1000) |
| `-b SIZE`, `--bytes=SIZE` | SIZE bytes per file (`K`, `M`, `G`, `KB`, `KiB`, ...) |
| `-n CHUNKS`, `--number=CHUNKS` | `N` equal byte chunks, `K/N` chunk K to stdout, `l/N` and `l/K/N` without splitting lines, `r/N` and `r/K/N` round-robin by line |
| `-a N`, `--suffix-length=N` | Fixed suffix length |
| `-d` | Decimal suffixes |
| `--numeric-suffixes[=FROM]` | Decimal suffixes, starting at FROM |
| `-x`, `--hex-suffixes[=FROM]` | Lowercase hex suffixes |
| `--additional-suffix=S` | Append S to every name |
| `-NUM` | Obsolete form of `-l NUM` |

Without `-a`, the suffix grows as needed: `xaa` ... `xyz`, then `xzaaa` ...; numerically `x00` ... `x89`, then `x9000` .... A fixed `-a N` that runs out stops with `split: output file suffixes exhausted` (exit 1). Combining `-l`, `-b`, and `-n` is an error. Not implemented, refused with exit 2: `-C`, `-t`, `-e`, `-u`, `--filter`, `--verbose`.

### Differences from GNU

- The whole input is buffered in memory.
- A very large chunk count is an error instead of an attempt to create that many files.

### Return type

No output objects (except `-n K/N`, which writes the chunk to stdout).

### Examples

```bash
seq 10 > s.txt
split -l 4 s.txt          # xaa xab xac
split -n 3 -d s.txt part_ # part_00 part_01 part_02, 7 bytes each
```

```bash
split -l 10 -d -a 4 huge.log part_   # part_0000, part_0001, ...
cat data.csv | split -l 500 - out_   # read the pipeline
```

## Pipeline bridge pattern

`head` and `tail` are pipeline bridges. They do not create new objects; they pass through the objects they receive, so type information survives the pipeline.

```powershell
# LsEntry objects survive through tail
$files = ls -la | tail -3
$files[0].PSObject.TypeNames[0]   # PsBash.LsEntry
$files[0].SizeBytes                # integer

# PsEntry objects survive through head
$procs = ps aux | sort -k4 -rn | head -5
$procs[0].PSObject.TypeNames[0]   # PsBash.PsEntry
$procs[0].Memory                   # double
```

Bridge commands can be chained, and the typed properties are still available at the end of the pipeline.
