`seq` generates numeric sequences, `expr` evaluates an arithmetic or string expression, `shuf` shuffles lines, and `yes` repeats a line until its reader stops.

---

## seq

Print a sequence of numbers, one per line or joined with a separator.

```
seq [OPTION]... LAST
seq [OPTION]... FIRST LAST
seq [OPTION]... FIRST INCREMENT LAST
```

### Flags

| Flag | Description |
|------|-------------|
| `-s SEP`, `--separator=SEP` | Join the numbers with SEP (one output record instead of one per number). `-sSEP` attached also works |
| `-w`, `--equal-width` | Pad with leading zeros to a common width |
| `-f FORMAT`, `--format=FORMAT` | printf-style floating format for each number: one `%e`, `%f`, or `%g` conversion with flags `-+ 0#`, width, and precision; `%%` is a literal `%` |

### Behavior

- Integer operands give integer output. If any operand has a decimal point, every value is printed with the largest number of decimal places among the operands (`seq 0 0.25 1` prints `0.00 ... 1.00`).
- Values are generated lazily: `seq 1 100000000 | head -1` computes one value.
- `FIRST > LAST` with a positive increment prints nothing.

### Differences from GNU

- `-w` pads integer sequences only; GNU also pads decimal sequences (`00.5`).
- A non-numeric operand is not reported with GNU's `invalid floating point argument` message.

### Exit status

0 on success. An explicit zero increment prints `seq: invalid Zero increment value: '0'` and exits 1. No operand (`seq: missing operand`) or a fourth one (`seq: extra operand ‘4’`) also prints `Try 'seq --help' for more information.` and exits 1.

### Properties

Without `-s`, each value is a `PsBash.SeqOutput` object:

| Property | Type | Description |
|----------|------|-------------|
| `Value` | long or double | The number (the text itself when `-f` makes it non-numeric) |
| `Index` | int | Zero-based position in the sequence |
| `BashText` | string | The printed text (with `-w` padding or `-f` formatting) |

With `-s`, seq writes one text record holding the joined values.

### Examples

**Count from 1 to 5:**

```bash
seq 5
```

```text
1
2
3
4
5
```

Each line is a typed object:

```powershell
$nums = seq 5
$nums[2].Value   # 3
$nums[2].Index   # 2
```

**Start, increment, end; count down:**

```bash
seq 0 2 10
seq 5 -1 1
```

```text
0
2
4
6
8
10
5
4
3
2
1
```

**Join with a separator:**

```bash
seq -s ', ' 1 5
```

```text
1, 2, 3, 4, 5
```

**Equal width and printf formats:**

```bash
seq -w 8 10
seq -f '%03g' 3
```

```text
08
09
10
001
002
003
```

**Decimal steps:**

```bash
seq 0.0 0.5 2.0
```

```text
0.0
0.5
1.0
1.5
2.0
```

## expr

Evaluate an expression, print the result, and set the exit status from it.

```
expr EXPRESSION
```

Each operand and operator is a separate argument: `expr 2 + 3`, not `expr 2+3`.

### Operators

| Form | Result |
|------|--------|
| `A + B`, `A - B`, `A * B`, `A / B`, `A % B` | Integer arithmetic with arbitrary precision; `/` truncates toward zero |
| `A < B`, `A <= B`, `A = B`, `A != B`, `A >= B`, `A > B` | `1` or `0`. Numeric comparison when both sides are integers, string comparison otherwise |
| `STRING : REGEX`, `match STRING REGEX` | REGEX is a POSIX basic regular expression anchored at the start. With `\(...\)` the result is the first group (empty on no match), otherwise the length of the match (`0` on no match) |
| `length STRING` | Length of STRING |
| `substr STRING POS LEN` | Substring from 1-based POS, at most LEN characters; empty when POS is out of range or LEN is below 1 |
| `index STRING CHARS` | 1-based position of the first character of STRING found in CHARS, or `0` |
| `A \| B` | A when it is neither empty nor `0`, otherwise B |
| `A & B` | A when neither side is empty or `0`, otherwise `0` |
| `( EXPRESSION )` | Grouping |
| `+ TOKEN` | TOKEN as a string, even when it is a keyword such as `length` |
| `STRING` | STRING itself |

Operators chain and follow GNU's precedence, lowest first: `|`, `&`, comparisons, `+ -`, `* / %`, `:`. Operators on one level group from the left, so `expr 1 + 2 + 3` prints `6` and `expr 2 + 3 '*' 4` prints `14`.

Quote `*`, `<`, `>`, `|`, `&`, `(`, and `)` so the shell does not treat them as operators: `expr '(' 1 + 2 ')' '*' 3`.

### Differences from GNU

- Strings compare by code point, which is GNU's order in the C locale. In another locale GNU uses that locale's collation order.

### Exit status

| Status | Meaning |
|--------|---------|
| 0 | Result is neither empty nor `0` |
| 1 | Result is empty or `0` |
| 2 | Error: `missing operand`, `syntax error: ...`, `division by zero`, `non-integer argument`, `invalid regular expression` |

The 0/1 rule is what makes `if expr "$name" : 'tmp_' >/dev/null; then ...` work.

### Properties

Each result is a `PsBash.ExprOutput` object:

| Property | Type | Description |
|----------|------|-------------|
| `Value` | long, BigInteger, or string | The result as a number when it is an integer, otherwise the text |
| `BashText` | string | The printed result |

### Examples

**Arithmetic:**

```bash
expr 2 + 3
expr 17 / 5
expr 17 % 5
expr '(' 1 + 2 ')' '*' 3
```

```text
5
3
2
9
```

```powershell
$r = expr 10 '*' 5
$r.Value   # 50
```

**Comparison:**

```bash
expr 10 '>' 5
```

```text
1
```

**String functions:**

```bash
expr length 'hello world'
expr substr 'hello world' 7 5
expr index 'hello' 'lo'
```

```text
11
world
3
```

**Regex match with a capture group:**

```bash
expr 'archive-2024.tar.gz' : '.*-\([0-9]*\)'
```

```text
2024
```

## shuf

Print input lines in random order.

```
shuf [OPTION]... [FILE]
shuf -e [OPTION]... [ARG]...
shuf -i LO-HI [OPTION]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-e` | Treat the arguments as the input lines |
| `-i LO-HI` | Input is the integers LO through HI |
| `-n N`, `--head-count=N` | Print at most N lines; of several `-n`, the smallest wins |
| `-r`, `--repeat` | Pick with replacement: N lines with `-n`, otherwise until the reader stops (`shuf -r -e a \| head -3`) |
| `-o FILE`, `--output=FILE` | Write to FILE after all input is read |

Without `-e` or `-i`, shuf reads FILE, or the pipeline when there is no FILE. A record without a trailing newline is joined to the next one first, as in every line consumer. A FILE that cannot be read prints `shuf: FILE: No such file or directory` and exits 1.

### Differences from GNU

- Not supported (exit 2): `-z`/`--zero-terminated`, `--random-source`. Options may come anywhere, also after `-e` (`shuf -e a b -n 1`), and take attached values (`-n3`), as in GNU. An unrecognized option prints `shuf: invalid option -- 'x'` and exits 1, and so do GNU's other usage errors (`cannot combine -e and -i options`, `invalid input range`, `invalid line count`, `extra operand`, `no lines to repeat`).
- The shuffle is unseeded; there is no way to reproduce an order.

### Return type

Pipeline input objects pass through unchanged (shuf only reorders them). Lines from `-e`, `-i`, or a file are text records.

### Examples

```bash
shuf -i 1-10 -n 3
shuf -e red green blue
ls *.jpg | shuf -n 1
```

## yes

Print a line repeatedly until the reading side stops.

```
yes [STRING]...
```

With no STRING, prints `y`. Several STRINGs are joined with a single space. There are no options other than `--help` and `--version`.

The loop stops when the downstream command stops reading, so `yes | head -n 3` terminates.

### Examples

```bash
yes | head -n 3
yes 'n o' | head -n 2
```

```text
y
y
y
n o
n o
```
