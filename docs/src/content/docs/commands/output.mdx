`echo` and `printf` follow the bash **builtins**, not the GNU coreutils programs: the option rules, escape dialects, and error messages are bash 5.2's.

## echo

Print the arguments, separated by single spaces, followed by a newline.

### Syntax

```text
echo [-neE] [STRING]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-n` | Do not print the trailing newline |
| `-e` | Interpret backslash escapes |
| `-E` | Do not interpret escapes (default) |

As in bash, only a leading run of words made of `n`, `e`, `E` after a dash are options (`-ne`, `-en`). The first other word ends option parsing and is printed literally, including `--`, `--help`, `-x`, and `-`. When both `-e` and `-E` are given, the last one wins.

### Escape sequences (`-e`)

| Sequence | Meaning |
|----------|---------|
| `\a` `\b` `\f` `\n` `\r` `\t` `\v` | Alert, backspace, form feed, newline, carriage return, tab, vertical tab |
| `\\` | Backslash |
| `\e`, `\E` | Escape (0x1B) |
| `\0NNN` | Byte with octal value NNN (up to three digits) |
| `\xHH` | Byte with hex value HH (one or two digits) |
| `\uHHHH`, `\UHHHHHHHH` | Unicode character |
| `\c` | Stop: nothing more is printed, not even the newline |

A bare `\NNN` without the leading `0` is not an escape in `echo`; it is printed as is. An unrecognized escape keeps its backslash.

### Return type

One `PsBash.TextOutput` per output line. `BashText` holds the line without its newline; with `-n` the last object is marked as having no trailing newline.

### Examples

```bash
echo one two three
```

```text
one two three
```

```bash
echo -e 'column1\tcolumn2\nrow1\trow2'
```

```text
column1	column2
row1	row2
```

```bash
echo -e '\x41\0102\cignored'; echo '|'
```

```text
AB|
```

```bash
echo -- -n     # `--` is not an option to echo
```

```text
-- -n
```

```powershell
$out = echo -n 'hello'
$out.BashText         # hello
```

### Comparison

```

Escapes are off by default (`xpg_echo` is off), as in bash.

```

## printf

Format and print arguments under control of a format string.

### Syntax

```text
printf [-v VAR] FORMAT [ARGUMENT]...
```

### Options

| Option | Description |
|--------|-------------|
| `-v VAR` | Assign the output to shell variable VAR instead of printing it. `VAR` may be an array element, `name[subscript]` |
| `--` | End of options |

Any other dash-led first word is an error: `printf: -x: invalid option` and the usage line, exit 2. With no format, printf prints the usage line and exits 2.

### Conversions

| Conversion | Description |
|------------|-------------|
| `%s` | String |
| `%b` | String with backslash escapes expanded (echo-style, plus `\NNN` octal) |
| `%q` | String quoted so the shell reads it back as the same word |
| `%c` | First character of the argument |
| `%d`, `%i` | Signed decimal |
| `%u` | Unsigned decimal |
| `%o`, `%x`, `%X` | Octal, hex, upper-case hex |
| `%f`, `%e`, `%E`, `%g`, `%G` | Floating point |
| `%(FMT)T` | `strftime` format of an epoch-seconds argument (`-1` or no argument means now) |
| `%%` | Literal `%` |

Flags `-`, `+`, space, `0`, `#`, a field width, and a precision are supported, and both width and precision may be `*` (taken from the next argument). Length modifiers (`h`, `l`, `L`, `j`, `z`, `t`) are accepted and ignored.

### Arguments

- The format is reused until every argument is consumed: `printf '%s\n' a b c` prints three lines.
- Numeric arguments are read like C `strtoimax`: `0x` hex, leading `0` octal, an optional sign. A leading quote gives the character code: `printf '%d' "'A"` prints `65`.
- A non-numeric argument to a numeric conversion prints `printf: X: invalid number` on stderr; printf continues and exits 1.
- An invalid conversion character prints what came before it, reports `` printf: `y': invalid format character ``, and exits 1.
- A conversion with no argument left gets an empty argument, as in bash: `%s` prints nothing, a numeric conversion prints `0`, and the width still applies. `printf '[%s][%d][%5s]\n' a` prints `[a][0][     ]`.

### Escape sequences in FORMAT

The format string expands `\a \b \e \f \n \r \t \v \\`, `\"`, `\'`, `\?`, `\NNN` (one to three octal digits), `\xHH`, `\uHHHH`, and `\UHHHHHHHH`. Unlike `echo` and `%b`, `\c` is not special in the format.

### Return type

One `PsBash.TextOutput` whose `BashText` is the exact formatted output. printf adds no newline of its own.

### Examples

```bash
printf '[%-6s][%5.2f][%03d][%x][%o]\n' ab 3.14159 7 255 8
```

```text
[ab    ][ 3.14][007][ff][10]
```

```bash
printf '%s=%d\n' a 1 b 2     # the format is reused
```

```text
a=1
b=2
```

```bash
printf '%q\n' "it's a test"
```

```text
it\'s\ a\ test
```

```bash
TZ=UTC printf '%(%Y-%m-%d)T\n' 0
printf -v out '%05.1f' 3.14159; echo "$out"
```

```text
1970-01-01
003.1
```

```bash
printf '%d\n' abc; echo "status=$?"
```

```text
printf: abc: invalid number
0
status=1
```

### Comparison

<Tabs>
<TabItem label="Bash">

```bash
printf 'Name: %s, Count: %d\n' 'items' 5
# Name: items, Count: 5
```

</TabItem>
<TabItem label="PsBash">

```powershell
printf 'Name: %s, Count: %d\n' 'items' 5
# Name: items, Count: 5
```

Same conversions, flags, and format reuse as the bash builtin.

</TabItem>
<TabItem label="PowerShell">

```powershell
'Name: {0}, Count: {1}' -f 'items', 5
# Name: items, Count: 5
```

PowerShell uses .NET composite format strings with `{0}`, `{1}` placeholders and the `-f` operator.

</TabItem>
</Tabs>
