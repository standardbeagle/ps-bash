Commands that change the filesystem. They print nothing unless asked to (`-v`, prompts, errors). Verbose lines are `PsBash.TextOutput` objects whose `BashText` is GNU's exact wording.

Shared conventions (coreutils 9.4):

- Options parse like GNU getopt: bundles (`-rfv`), options after operands, unique long-option abbreviations (`--rec`), and `--` to end options. `chmod` takes its long options in full only; `install` and `mktemp` have their own rules, given in their sections.
- Unknown options and usage errors use GNU's wording and exit 1. A GNU option that ps-bash does not implement exits 2 with `recognized but not supported`.
- Diagnostics name an operand as you typed it (`cp: cannot stat 'nosuch': No such file or directory`). Paths in `-v` output use forward slashes.
- `-i` prompts go to stderr, and the answer is read from the command's stdin. No answer counts as "no". An answer starting with `y` or `Y` is yes.

## cp

Copy files and directories.

```
cp [OPTION]... SOURCE DEST
cp [OPTION]... SOURCE... DIRECTORY
cp [OPTION]... -t DIRECTORY SOURCE...
```

### Flags

| Flag | Description |
|------|-------------|
| `-r`, `-R`, `--recursive` | Copy directories recursively |
| `-a`, `--archive` | `-dR --preserve=all` |
| `-p` | `--preserve=mode,ownership,timestamps` |
| `--preserve[=LIST]`, `--no-preserve=LIST` | Attributes to keep: `mode`, `timestamps`, `ownership`, `links`, `context`, `xattr`, `all` |
| `-f`, `--force` | Overwrite a read-only destination; with `-l`/`-s`, replace an existing destination |
| `-n`, `--no-clobber` | Do not overwrite an existing file |
| `-i`, `--interactive` | Ask before overwriting |
| `-u`, `--update[=WHEN]` | `older` (default): copy only when the source is newer; `all`; `none` |
| `-v`, `--verbose` | Name each file copied |
| `-l`, `--link` / `-s`, `--symbolic-link` | Make hard links / symbolic links instead of copying |
| `-b`, `--backup[=CONTROL]`, `-S SUFFIX` | Back up an existing destination (`none`, `simple`, `existing`, `numbered`) |
| `-t DIR`, `--target-directory=DIR` | Copy all sources into DIR |
| `-T`, `--no-target-directory` | Treat DEST as a file, never as a directory to copy into |
| `--parents` | Recreate each source's path under the destination directory |
| `-L` / `-H` / `-P` / `-d` | Follow links always / on the command line only / never / never and keep links |
| `-x`, `--one-file-system` | Do not descend into another device |
| `--remove-destination` | Remove the destination before copying |
| `--attributes-only` | Copy attributes, not data |
| `--reflink[=WHEN]`, `--sparse=WHEN` | Accepted. `--reflink` and `--reflink=always` fail: no supported filesystem clones |
| `--strip-trailing-slashes`, `--debug` | As GNU |

Refused (exit 2): `-Z`/`--context`, `--copy-contents`.

### Behavior

- The last of `-i`, `-n` and `--update=none|all` decides the overwrite policy. `-f` does not cancel `-i`.
- `-n` prints GNU 9.4's warning `cp: warning: behavior of -n is non-portable and may change in future; use --update=none instead` and skips existing files with status 0.
- `cp a b` where `b` is the same file (a hard link, or a symlink to it) fails with `'a' and 'b' are the same file`, status 1.
- A missing destination parent is an error (`cp: cannot create regular file 'nodir/x': No such file or directory`). Parent directories are not created for you.
- A copy that does not preserve timestamps gets the current time, as in GNU.
- On Windows, `mode` preservation copies the read-only, hidden and archive attributes. `ownership`, `links` and `xattr` are accepted and do nothing. `--preserve=context` fails, as on a kernel without SELinux.

### Examples

```bash
cp -rv src dst
```

```text
'src' -> 'dst'
'src/a' -> 'dst/a'
'src/b' -> 'dst/b'
```

```bash
cp -bv x src/a                       # 'x' -> 'src/a' (backup: 'src/a~')
cp --update=none defaults.json settings.json
cp -t dest/ file1.txt file2.txt
cp --parents src/lib/util.sh out/    # creates out/src/lib/util.sh
cp -a project project.bak
```

## mv

Move or rename files and directories.

```
mv [OPTION]... SOURCE DEST
mv [OPTION]... SOURCE... DIRECTORY
mv [OPTION]... -t DIRECTORY SOURCE...
```

### Flags

| Flag | Description |
|------|-------------|
| `-f`, `--force` | Do not prompt before overwriting |
| `-n`, `--no-clobber` | Do not overwrite; say so (`mv: not replacing 'b'`) and exit 1 |
| `-i`, `--interactive` | Ask before overwriting (`mv: overwrite 'b'? `) |
| `-u`, `--update[=WHEN]` | Move only when the source is newer (`older`), or `all` / `none` |
| `-v`, `--verbose` | Print `renamed 'a' -> 'b'` |
| `-b`, `--backup[=CONTROL]`, `-S SUFFIX` | Back up an existing destination |
| `-t DIR`, `--target-directory=DIR` | Move all sources into DIR |
| `-T`, `--no-target-directory` | Treat DEST as a file |

The last of `-f`, `-n`, `-i` and `--update=none|all` decides. Refused (exit 2): `-Z`/`--context`, `--strip-trailing-slashes`, `--no-copy`, `--debug`.

### Behavior

- Hard links to the same file are `'a' and 'b' are the same file` (status 1). Moving a file onto a symlink that points at it replaces the symlink, as in GNU.
- A declined `-i` prompt exits 1.
- A missing destination parent: `mv: cannot move 's' to 'nodir/x': No such file or directory`.

### Examples

```bash
mv -v a c                  # renamed 'a' -> 'c'
mv -n draft.md final.md    # mv: not replacing 'final.md'   (status 1)
mv -t archive/ *.log
mv --backup=numbered new.conf app.conf
```

## rm

Remove files or directories.

```
rm [OPTION]... FILE...
```

### Flags

| Flag | Description |
|------|-------------|
| `-r`, `-R`, `--recursive` | Remove directories and their contents |
| `-d`, `--dir` | Remove empty directories |
| `-f`, `--force` | Ignore missing files, never prompt |
| `-i` | Prompt before every removal |
| `-I` | Prompt once before removing more than three files, or when recursive |
| `--interactive[=WHEN]` | `never`, `once` (`-I`), `always` (`-i`) |
| `-v`, `--verbose` | Name each file removed |
| `--preserve-root[=all]` | Refuse to remove `/` recursively (default). `=all` also skips operands on another device |
| `--no-preserve-root` | Turn the GNU failsafe off (the protected-path guard below still applies) |
| `--one-file-system` | Skip directories on another device than the operand |

The last of `-f`, `-i`, `-I` and `--interactive` wins.

### Behavior

- Prompts use GNU's text: `rm: remove regular file 'x'? `, `rm: remove regular empty file 'x'? `, `rm: descend into directory 'd'? `, `rm: remove 4 arguments? `.
- `.` and `..` operands are refused: `rm: refusing to remove '.' or '..' directory: skipping '.'`.
- `rm -r /` (also `C:/`, `//`) prints GNU's `rm: it is dangerous to operate recursively on '/'` and `rm: use --no-preserve-root to override this failsafe`.

<Aside type="caution" title="Protected paths">
On top of GNU's checks, `rm` never removes a filesystem root (`/`, `C:\`) or your home directory, even with `--no-preserve-root`: `rm: refusing to remove 'C:/Users/you': protected path`. Windows reserved device names (`NUL`, `CON`, ...) are not deleted either.
</Aside>

### Examples

```bash
rm -rv b
```

```text
removed 'b/c/f'
removed directory 'b/c'
removed directory 'b'
```

```bash
rm -f maybe-missing.txt
rm -d empty-dir
rm -I *.log
```

## mkdir

Create directories.

```
mkdir [OPTION]... DIRECTORY...
```

### Flags

| Flag | Description |
|------|-------------|
| `-p`, `--parents` | Create missing parents; no error if the directory exists |
| `-v`, `--verbose` | Print `mkdir: created directory 'd'` for each directory created |
| `-m MODE`, `--mode=MODE` | Mode of the new directory: octal or symbolic (`u=rwx,go=rx`, `a+x`, `+t`) |

`-m` is checked before anything is created. A bad mode is `mkdir: invalid mode 'X'` (exit 1). With `-p`, only the last directory gets the mode. Refused (exit 2): `-Z`/`--context`.

### Differences from GNU

On Windows only the owner-write bit maps to anything: a mode without it sets the read-only attribute. Other bits are accepted and have no effect.

### Examples

```bash
mkdir -p src/components/ui
mkdir -pv p/q
```

`-pv` reports every directory it creates, named as typed:

```text
mkdir: created directory 'p'
mkdir: created directory 'p/q'
```

```bash
mkdir -m 700 secrets
```

## rmdir

Remove empty directories.

```
rmdir [OPTION]... DIRECTORY...
```

### Flags

| Flag | Description |
|------|-------------|
| `-p`, `--parents` | Also remove each parent directory named in the operand: `rmdir -p a/b/c` removes `a/b/c`, `a/b`, then `a` |
| `-v`, `--verbose` | Print `rmdir: removing directory, 'd'`, with the name as typed |

Refused (exit 2): `--ignore-fail-on-non-empty`.

`-p` stops at the operand's first component. It never removes a directory above that component, even an empty one. If a parent is not empty, `rmdir` reports it (`rmdir: failed to remove directory 'a': Directory not empty`) and exits 1.

### Examples

```bash
rmdir -pv a/b/c
```

```text
rmdir: removing directory, 'a/b/c'
rmdir: removing directory, 'a/b'
rmdir: removing directory, 'a'
```

```bash
rmdir src       # rmdir: failed to remove 'src': Directory not empty   (status 1)
```

## touch

Create files or change their timestamps.

```
touch [OPTION]... FILE...
```

### Flags

| Flag | Argument | Description |
|------|----------|-------------|
| `-a` | -- | Change only the access time |
| `-m` | -- | Change only the modification time |
| `--time` | WORD | `atime`/`access`/`use` = `-a`, `mtime`/`modify` = `-m` |
| `-c`, `--no-create` | -- | Do not create missing files |
| `-d`, `--date` | STRING | Use a GNU date string instead of now |
| `-t` | STAMP | `[[CC]YY]MMDDhhmm[.ss]`, local time |
| `-r`, `--reference` | FILE | Use FILE's times |
| `-h`, `--no-dereference` | -- | Change a symlink itself, not its target |
| `-f` | -- | Ignored, as in GNU |

### Behavior

- `-d` takes the same strings as `date -d`: `3 hours ago`, `yesterday`, `next friday`, `2024-01-02 10:00`, `@1700000000`, zone suffixes. An impossible date or trailing junk is `touch: invalid date format 'X'` (exit 1).
- `-t` with `-d` or `-r` is `touch: cannot specify times from more than one source` (exit 1).
- Without `-h`, a symlink is resolved first, so a dangling link creates its target.
- Missing parent directories are not created.

### Examples

```bash
touch notes.txt
touch -d '2024-01-02 10:00' report.txt
touch -t 202401021030.00 report.txt
touch -r reference.txt copy.txt
touch -c maybe-missing.txt     # no file is created
```

## ln

Create hard or symbolic links.

```
ln [OPTION]... TARGET LINK_NAME
ln [OPTION]... TARGET
ln [OPTION]... TARGET... DIRECTORY
ln [OPTION]... -t DIRECTORY TARGET...
```

### Flags

| Flag | Description |
|------|-------------|
| `-s`, `--symbolic` | Make a symbolic link instead of a hard link |
| `-f`, `--force` | Replace an existing LINK_NAME |
| `-i`, `--interactive` | Ask before replacing (`ln: replace 'b'? `) |
| `-r`, `--relative` | Store the target relative to the link's directory (needs `-s`) |
| `-v`, `--verbose` | Print each link made |
| `-n`, `--no-dereference` | Accepted (a symlink-to-directory LINK_NAME is never descended into) |
| `-b`, `--backup[=CONTROL]`, `-S SUFFIX` | Back up an existing LINK_NAME |
| `-t DIR`, `--target-directory=DIR` | Make the links in DIR |
| `-T`, `--no-target-directory` | Treat LINK_NAME as a file |

Refused (exit 2): `-d`/`-F`/`--directory`, `-L`/`--logical`, `-P`/`--physical`.

### Differences from GNU

- GNU follows a LINK_NAME that is a symlink to a directory unless `-n` is given. ps-bash always treats it as a plain name.
- With `-r` on Windows, targets on two different drives have no relative path, so the absolute target is stored.

### Examples

```bash
ln -v original.txt hardlink.txt     # 'hardlink.txt' => 'original.txt'
ln -sv config.json config-link.json # 'config-link.json' -> 'config.json'
ln -sfv /new/target existing-link
ln -srv f d2/                       # 'd2/f' -> '../f'
```

<Aside type="caution" title="Windows symlinks">
Creating symbolic links on Windows needs Developer Mode or an elevated session. A failure is reported (`ln: failed to create symbolic link ...`), never ignored. Hard links need no privilege but must stay on one NTFS volume.
</Aside>

## chmod

Change file mode bits.

```
chmod [OPTION]... MODE FILE...
```

### Flags

| Flag | Description |
|------|-------------|
| `-R`, `--recursive` | Change directories and their contents (symlinks met in the walk are skipped) |
| `-v`, `--verbose` | Report every file |
| `-c`, `--changes` | Report only files whose mode changed |
| `-f`, `--silent`, `--quiet` | Suppress most error messages |
| `--preserve-root`, `--no-preserve-root` | Accepted |

MODE is octal (`644`) or symbolic (`u+x`, `go-w`, `a=r`, `+x`, `g=u`, and comma lists). A dash-leading symbolic mode such as `-w` or `-x` is taken as the MODE, not as an option. An invalid mode is `chmod: invalid mode: 'X'` (exit 1) and no file is touched. A missing file is `chmod: cannot access 'x': No such file or directory`. The other files are still changed and the status is 1.

Not supported: `--reference=FILE` (an error, exit 1).

### Differences from GNU

Windows has no mode bits. Only the owner-write bit maps, to the read-only attribute: `chmod -w f` and `chmod 444 f` set it, `chmod +w f` and `chmod 644 f` clear it. Every other bit is accepted and changes nothing, so `chmod +x script.sh` succeeds, as it does in Git Bash. `-v`/`-c` report the stand-in modes `0644`/`0755` (`0444`/`0555` when read-only). On Linux and macOS the bits are set exactly.

### Examples

```bash
chmod +x build.sh
chmod -v 444 f
```

```text
mode of 'f' changed from 0644 (rw-r--r--) to 0444 (r--r--r--)
```

```bash
chmod -R go-w public/
```

## install

Copy files into place, or create directories.

```
install [OPTION]... SOURCE DEST
install [OPTION]... SOURCE... DIRECTORY
install [OPTION]... -t DIRECTORY SOURCE...
install -d [OPTION]... DIRECTORY...
```

### Flags

| Flag | Argument | Description |
|------|----------|-------------|
| `-d` | -- | Create each operand as a directory, with parents |
| `-D` | -- | Create the destination's leading directories, then copy |
| `-t` | DIR | Copy all sources into DIR (created if missing) |
| `-m` | MODE | Accepted; the mode is not applied |
| `-s` | -- | Accepted; binaries are not stripped |
| `-S` | SUFFIX | Suffix for the swapped-aside old file (default `.old`) |
| `-v` | -- | Report each copy and directory |

### Behavior

- When the destination exists, it is renamed to `DEST.old` (the `-S` suffix) and the new file is copied in, so `install` can replace a binary that is in use. On Linux and macOS the old file is then deleted. On Windows its deletion is scheduled for the next reboot, so `DEST.old` stays on disk until then; it is deleted at once only if the scheduling call fails.
- A copy creates the destination's parent directory if it is missing.
- Options are matched case-sensitively and cannot be bundled: write `-d -v`, not `-dv`.

### Differences from GNU

- `-m` and `-s` have no effect, and `-o`/`-g` are not supported. Install the file, then run `chmod` if the mode matters.
- `-S` names the swap suffix. In GNU it is the backup suffix.
- `-d` and `-D` are told apart by the operands, not by case. With no `-t` and no operand that is an existing file, the flag creates directories. Otherwise it creates leading directories for the copy.
- `--` ends options. Long options (`--mode=...`, `--target-directory=...`) are not recognized.
- `-v` names files and directories as typed (`'a' -> 'b'`, `install: creating directory 'x/y'`), as GNU does. One line differs: a replaced destination is reported as `install: swapped 'C:/work/b' -> 'C:/work/b.old'`, with full paths, where GNU prints `removed 'b'`.
- With no operands, the message is `install: missing file operand` without the `Try 'install --help'` hint. The exit status is 1, as in GNU.

### Examples

```bash
install -v a b             # 'a' -> 'b'
install -d -v x/y          # install: creating directory 'x', then 'x/y'
install -t ~/.local/bin ps-bash.exe
install -D build/app.exe dist/bin/app.exe
```

## mktemp

Create a uniquely named temporary file or directory and print its name.

```
mktemp [OPTION]... [TEMPLATE]
```

### Flags

| Flag | Description |
|------|-------------|
| `-d`, `--directory` | Create a directory instead of a file |
| `-p DIR`, `--tmpdir[=DIR]` | Create the entry in DIR. `--tmpdir` with no DIR uses `$TMPDIR`, else the default directory |
| `-t` | Create the entry in `$TMPDIR`, else the `-p` DIR, else the default directory |
| `--suffix=SUFFIX` | Append SUFFIX to the name. The TEMPLATE must then end in `X` |
| `-u`, `--dry-run` | Print a free name without creating anything |
| `-q`, `--quiet` | Print no message when creation fails |

### Behavior

- A TEMPLATE needs a run of at least three `X`. The last run is replaced with random letters and digits, one for each `X`: `mktemp app.XXXXXX` gives a name such as `app.lEqs45`. The default TEMPLATE is `tmp.XXXXXXXXXX`.
- A TEMPLATE on its own is a path relative to the current directory, and may name a directory that exists: `mktemp build/app.XXXXXX`.
- With no TEMPLATE, or with `-p`, `--tmpdir`, or `-t`, the entry goes into the directory the table above names. With no TEMPLATE and no option, that is `$TMPDIR`, else the default directory. `TMPDIR` counts only when it is exported.
- The default directory is the `ps-bash/proc-sub/` folder of the system temp directory.
- Files are created exclusively (never adopting an existing path), and with owner-only permissions on Linux and macOS (0600 file, 0700 directory).
- The printed name keeps the directory as typed (`sub/in.WihIn2`, or `C:/Users/you/AppData/Local/Temp/ps-bash/proc-sub/tmp.EjPBGsc3qo` for the default directory). The output object also has a `Path` property with the native path.

Errors exit 1 with GNU's messages: `mktemp: too few X's in template ‘app.XX’`, `mktemp: too many templates`, and `mktemp: failed to create file via template ‘sub/app.XXXXXX’: No such file or directory` when the directory is missing.

### Differences from GNU

- The default directory is ps-bash's temp folder, not `/tmp`. Set and export `TMPDIR` to choose another.

### Examples

```bash
tmp=$(mktemp)
dir=$(mktemp -d)
work=$(mktemp -d build.XXXXXX)        # in the current directory
log=$(mktemp --suffix=.log run.XXXXXX)
export TMPDIR=$PWD/scratch            # from here, mktemp and mktemp -t create files in scratch/
trap 'rm -rf "$dir"' EXIT
```

## Cross-platform notes

<Tabs>
<TabItem label="Path separators">

All commands accept `/` and `\` (and `/c/x`, `/mnt/c/x`) as input. Their own output, including `-v` lines and error messages, uses forward slashes.

</TabItem>
<TabItem label="Symlinks on Windows">

`ln -s` and `cp -s` need **Developer Mode** (Settings > System > For developers) or an elevated session. Hard links (`ln`, `cp -l`) need no elevation but must stay on one NTFS volume. Tests and scripts that only need a directory link can use a junction instead.

</TabItem>
<TabItem label="Permissions">

- **Linux/macOS**: `chmod`, `mkdir -m` and `cp -p` set real permission bits.
- **Windows**: NTFS has ACLs, not mode bits. Only the owner-write bit maps, to the read-only attribute. `ls -l` and `stat` show synthesized modes (0644 files, 0755 directories and executables).

</TabItem>
</Tabs>
