## jq

JSON processor. `jq` is a .NET implementation of the jq 1.7 language: jq's grammar, generator semantics, path expressions, user-defined functions, regular expressions, and `@format` strings. The gaps are listed under [Not supported](#not-supported). It is checked against the jq 1.7 binary in more than 300 differential tests.

```text
jq [OPTIONS] FILTER [FILE...]
jq [OPTIONS] --args FILTER [STRING...]
jq [OPTIONS] --jsonargs FILTER [JSON_TEXT...]
```

Options can appear anywhere and short options can be bundled (`-nr`). The first non-option word is the filter. With `-f`, it names a file that holds the filter. Without a filter, jq uses `.`. The remaining words are input files, or positional values after `--args` or `--jsonargs`. Without files, jq reads pipeline input.

### Flags

| Flag | Description |
|------|-------------|
| `-n`, `--null-input` | Run the filter once with `null` as input. Read inputs with `input`/`inputs` |
| `-r`, `--raw-output` | Print strings without quotes |
| `-j`, `--join-output` | Like `-r`, with no newline after each result |
| `-a`, `--ascii-output` | Escape non-ASCII characters as `\uXXXX` |
| `-c`, `--compact-output` | One result per line, no whitespace |
| `-s`, `--slurp` | Read all inputs into one array (with `-R`, into one string) |
| `-S`, `--sort-keys` | Sort object keys on output |
| `-R`, `--raw-input` | Read each input line as a string instead of parsing JSON |
| `-e`, `--exit-status` | Set the exit status from the last output (see below) |
| `-f`, `--from-file` | Read the filter from the file named by the first operand |
| `--tab` | Indent with tabs. `-c` overrides it |
| `--indent N` | Indent by `N` spaces (`-1` to `7`). Larger values are an error, exit 2 |
| `--stream` | Emit `[path, leaf]` events instead of whole values |
| `--seq` | Prefix each output with the RS character (output side only) |
| `--arg NAME VALUE` | Bind `$NAME` to the string `VALUE`. The first binding of a repeated name wins |
| `--argjson NAME JSON` | Bind `$NAME` to parsed JSON |
| `--slurpfile NAME FILE` | Bind `$NAME` to an array of the JSON values in `FILE` |
| `--rawfile NAME FILE` | Bind `$NAME` to the text of `FILE` |
| `--args` | Treat the remaining operands as strings in `$ARGS.positional` |
| `--jsonargs` | Treat the remaining operands as JSON values in `$ARGS.positional` |
| `-M`, `--monochrome-output`, `--unbuffered` | Accepted. Output is never colored or buffered |
| `-h`, `--help`, `-V`, `--version` | Help, or `jq-1.7` |

### Exit status

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | With `-e`: the last output was `false` or `null` |
| 2 | Usage error, unknown option, missing input file |
| 3 | Compile error (undefined function or variable, syntax error), reported before any input is read |
| 4 | With `-e`: no output |
| 5 | Runtime error or malformed input, from the last input processed |

`halt_error` exits with the status it is given. Runtime errors use jq's format: `jq: error (at <stdin>:3): Cannot index number with "name"`. JSON parse errors include jq's line and column: `jq: parse error: Invalid numeric literal at line 1, column 6`.

### Language

Supported syntax:

- Paths and iteration: `.a.b`, `.[0]`, `.[-1]`, `.[2:4]`, `.[]`, `.[]?`, `..`, `."key"`, `.["key"]`
- Operators: `|`, `,`, `//`, `and`/`or`/`not`, arithmetic, comparison, and the assignments `=`, `|=`, `+=`, `-=`, `*=`, `/=`, `%=`, `//=`
- Control flow: `if`/`elif`/`else`/`end`, `try`/`catch`, `reduce`, `foreach`, `label $name | ... break $name`, optional `?`
- Bindings: `. as $x`, destructuring (`. as [$a, {b: $c}]`) with `?//` alternatives, `$ENV`, `$__loc__`, `$ARGS`
- Functions: `def f: ...;`, `def f(g; $x): ...;`, recursion, closures
- Strings: interpolation `"\(.x)"`, and the formats `@text`, `@json`, `@csv`, `@tsv`, `@html`, `@uri`, `@sh`, `@base64`, `@base64d`
- Numbers keep their literal text until arithmetic touches them, as in jq 1.7 (`1.50` prints as `1.50`, and `100000000000000000000` prints in full)

### Built-in functions

| Group | Functions |
|-------|-----------|
| Types and values | `length`, `utf8bytelength`, `type`, `keys`, `keys_unsorted`, `values`, `has`, `in`, `contains`, `inside`, `empty`, `error`, `not`, `tostring`, `tonumber`, `tojson`, `fromjson`, `arrays`, `objects`, `iterables`, `booleans`, `numbers`, `normals`, `finites`, `strings`, `nulls`, `scalars` |
| Arrays | `map`, `map_values`, `add`, `any`, `all`, `flatten`, `range`, `reverse`, `sort`, `sort_by`, `group_by`, `unique`, `unique_by`, `min`, `max`, `min_by`, `max_by`, `index`, `rindex`, `indices`, `first`, `last`, `nth`, `combinations`, `transpose`, `join`, `implode`, `explode` |
| Objects | `to_entries`, `from_entries`, `with_entries`, `del`, `pick`, `walk`, `env` |
| Paths | `path`, `paths`, `getpath`, `setpath`, `delpaths`, `tostream`, `fromstream`, `truncate_stream` |
| Generators | `recurse`, `select`, `limit`, `until`, `while`, `repeat`, `isempty`, `input`, `inputs` |
| Strings | `ascii_downcase`, `ascii_upcase`, `ltrimstr`, `rtrimstr`, `startswith`, `endswith`, `split`, `splits`, `test`, `match`, `capture`, `scan`, `sub`, `gsub` |
| Math | `abs`, `floor`, `ceil`, `round`, `trunc`, `sqrt`, `cbrt`, `pow`, `log`, `log2`, `log10`, `exp`, `exp2`, `exp10`, trigonometric and hyperbolic functions, `atan2`, `fma`, `fmin`, `fmax`, `ldexp`, `copysign`, `infinite`, `nan`, `isinfinite`, `isnan`, `isnormal` |
| Other | `debug`, `stderr`, `input_filename`, `input_line_number`, `builtins`, `halt`, `halt_error`, `now` |

Regular expressions use Oniguruma syntax translated to .NET. Match offsets count code points, as in jq.

### Not supported

- `-C` / color output: `jq: Unknown option -C`, exit 2
- Date functions other than `now` (`strftime`, `strptime`, `mktime`, `gmtime`, `todate`, `fromdate`, ...): compile error, exit 3
- Modules (`import`, `include`), `--seq` on input, and `$__prog_args`

### Differences from jq 1.7

- `debug`, `stderr`, and `halt_error` write one stderr line per call. `stderr` output ends in a newline, which jq does not add.
- After an input file that cannot be read, the later files are still read in full.
- Syntax errors do not include bison's `expecting ...` token list.
- `$ENV.PATH` also works on Windows, where the variable is named `Path`.

### Return type

Each result is one text record. A pretty-printed object or array is a single multi-line record. With `-j`, records carry no trailing newline.

### Examples

**Extract a nested field:**

```bash
echo '{"database": {"host": "localhost", "port": 5432}}' | jq '.database.host'
```

```text
"localhost"
```

**Raw output (no quotes):**

```bash
echo '{"name": "alice"}' | jq -r '.name'
```

```text
alice
```

**Iterate array elements:**

```bash
echo '[1, 2, 3]' | jq '.[]'
```

```text
1
2
3
```

**Select with a condition:**

```bash
echo '[{"name": "alice", "age": 30}, {"name": "bob", "age": 17}]' | jq '.[] | select(.age >= 21)'
```

```text
{
  "name": "alice",
  "age": 30
}
```

**Map over an array:**

```bash
echo '[1, 2, 3]' | jq -c 'map(. * 2)'
```

```text
[2,4,6]
```

**Sort keys:**

```bash
echo '{"z": 1, "a": 2}' | jq -S '.'
```

```text
{
  "a": 2,
  "z": 1
}
```

**Slurp multiple JSON values into an array:**

```bash
printf '{"a":1}\n{"b":2}\n' | jq -c -s '.'
```

```text
[{"a":1},{"b":2}]
```

**Construct a new object:**

```bash
echo '{"first": "alice", "last": "smith", "age": 30}' | jq -c '{fullName: "\(.first) \(.last)", age}'
```

```text
{"fullName":"alice smith","age":30}
```

**Update in place with a path assignment:**

```bash
echo '{"version": "1.2.3", "deps": {"a": 1}}' | jq -c '.deps.b = 2 | .version |= "v" + .'
```

```text
{"version":"v1.2.3","deps":{"a":1,"b":2}}
```

**Pass shell values in safely:**

```bash
jq -n -c --arg user "$USER" --argjson n 3 '{user: $user, n: $n}'
```

**Aggregate with reduce:**

```bash
echo '[{"k":"a","v":1},{"k":"b","v":2},{"k":"a","v":5}]' | jq -c 'reduce .[] as $x ({}; .[$x.k] += $x.v)'
```

```text
{"a":6,"b":2}
```

**Emit CSV:**

```bash
echo '[["name","age"],["alice",30]]' | jq -r '.[] | @csv'
```

```text
"name","age"
"alice",30
```

**Read raw lines and test with a regex:**

```bash
printf 'error: disk\nok\nerror: net\n' | jq -R 'select(test("^error")) | sub("^error: "; "")'
```

```text
"disk"
"net"
```

**Fail a script when a field is missing:**

```bash
jq -e '.version' package.json >/dev/null || echo 'no version'
```

## yq

YAML processor for simple YAML files. `yq` is not mikefarah/yq or the Python yq. It parses a subset of YAML and applies a small jq-style filter language. Output is JSON by default.

```text
yq [-r] [-o json|yaml] [FILTER] [FILE...]
```

### Flags

| Flag | Description |
|------|-------------|
| `-r`, `--raw-output` | Print strings without quotes |
| `-o FORMAT`, `--output-format FORMAT` | `json` (default) or `yaml` |
| `--help`, `--version` | Help or version |

### Supported YAML

- Block mappings nested by indentation (`key: value`, `key:` followed by an indented block)
- Block sequences of scalars (`- item`)
- Scalars: integers, decimals, `true`, `false`, `null`, `~`, and single- or double-quoted strings
- `#` comment lines and blank lines are skipped

Flow collections (`{a: 1}`, `[1, 2]`), sequences of mappings (`- name: x`), anchors and aliases, block scalars (`|`, `>`), multi-document streams, and JSON input are not parsed.

### Filter language

yq does not use the jq engine. Its filter language supports:

- `.`, `.a.b`, `.[0]`, `.[]`, `..`
- `|`, `,`, `//`, `if ... then ... elif ... else ... end`, `EXPR as $var | ...`
- `[EXPR]`, `{key: EXPR}`, `{key}`, string interpolation `"\(.x)"`
- `keys`, `values`, `length`, `type`, `not`, `map(EXPR)`, `select(EXPR)`. `select` accepts one comparison (`==`, `!=`, `<`, `<=`, `>`, `>=`) or a truthiness test
- number, string, `true`, `false`, and `null` literals

For anything else, convert to JSON with `yq '.'` and pipe the result to `jq`.

### Return type

Each result is one text record holding JSON or YAML.

### Examples

**Extract a field from YAML:**

```bash
printf 'database:\n  host: localhost\n  port: 5432\n' | yq '.database.host'
```

```text
"localhost"
```

**Raw output:**

```bash
echo "name: alice" | yq -r '.name'
```

```text
alice
```

**Convert YAML to JSON:**

```bash
printf 'name: alice\nage: 30\ntags:\n  - admin\n  - user\n' | yq '.'
```

```text
{
  "name": "alice",
  "age": 30,
  "tags": [
  "admin",
  "user"
]
}
```

The JSON is valid, but the elements of a nested array are not indented one level deeper. Pipe through `jq .` for conventional layout.

**Filter nested YAML and output as YAML:**

```bash
printf 'services:\n  web:\n    port: 8080\n  db:\n    port: 5432\n' | yq -o yaml '.services.web'
```

```text
port: 8080
```

**Hand off to jq for the rest:**

```bash
yq '.' config.yaml | jq -r '.services | to_entries[] | "\(.key)=\(.value.port)"'
```

## xan

Minimal CSV toolkit with five subcommands. It is not the full `xan` tool. Fields are split on the delimiter with no quote handling, so a quoted field that contains the delimiter is split.

```text
xan [-d DELIM] SUBCOMMAND [ARGS...] [FILE]
```

Without `FILE`, xan reads pipeline input. The first line is the header, and empty data lines are skipped.

### Global flags

| Flag | Description |
|------|-------------|
| `-d DELIM` | Field delimiter (default `,`). Can be more than one character |

### Subcommands

| Subcommand | Description |
|------------|-------------|
| `headers [FILE]` | Print each column name on its own line |
| `count [FILE]` | Print the number of data rows |
| `select COLS [FILE]` | Print the named columns (comma-separated) for the header and every row. An unknown column prints empty values |
| `search REGEX [FILE]` | Print the header, then each row matching the .NET regular expression `REGEX` |
| `table [FILE]` | Print the data as columns padded with two spaces |

A missing subcommand or an unknown one is an error with exit 1.

### Return type

`headers`, `select`, and `search` return one text record per line. `count` returns a single record. `table` returns the whole table as one multi-line record.

### Examples

**List column names:**

```bash
printf 'name,age,city\nalice,30,portland\nbob,25,seattle\n' | xan headers
```

```text
name
age
city
```

**Count rows:**

```bash
printf 'name,age\nalice,30\nbob,25\ncarol,35\n' | xan count
```

```text
3
```

**Select specific columns:**

```bash
printf 'name,age,city\nalice,30,portland\nbob,25,seattle\n' | xan select name,city
```

```text
name,city
alice,portland
bob,seattle
```

**Search for a pattern:**

```bash
printf 'name,age,city\nalice,30,portland\nbob,25,seattle\ncarol,35,portland\n' | xan search portland
```

```text
name,age,city
alice,30,portland
carol,35,portland
```

**Pretty-print as a table:**

```bash
printf 'name,age,city\nalice,30,portland\nbob,25,seattle\n' | xan table
```

```text
name   age  city
alice  30   portland
bob    25   seattle
```

`table` pads every cell to its column width, including the last cell of a row, and writes the whole table as one record. On Windows the rows are separated by CRLF, so add `tr -d '\r'` before a command that counts bytes or matches line ends.

**Tab-separated input:**

```bash
printf 'name\tage\nalice\t30\n' | xan -d "$(printf '\t')" headers
```

```text
name
age
```

### jq + xan together

```bash
# Extract names from a JSON array, format as CSV, then align
echo '[{"name":"alice","age":30},{"name":"bob","age":25}]' \
  | jq -r '["name","age"], (.[] | [.name, .age]) | @csv' | tr -d '"' | xan table
```

<Aside type="tip">
All three commands accept pipeline input or file arguments. With pipeline input, they read the `BashText` of each incoming object, so they compose with every other ps-bash command.
</Aside>
