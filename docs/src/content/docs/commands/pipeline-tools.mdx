## tee

Copy pipeline input to one or more files while passing the original typed objects through to the next command.

### Syntax

```text
tee [-a] [FILE]...
```

### Flags

| Flag | Description |
|------|-------------|
| `-a`, `--append` | Append to the files instead of overwriting them |
| `-i`, `--ignore-interrupts` | Accepted; tee is never stopped by an interrupt it does not own |
| `-p`, `--output-error[=MODE]` | Accepted for every MODE (`warn`, `warn-nopipe`, `exit`, `exit-nopipe`): a reader that closes early stops tee without an error. Another MODE is GNU's `invalid argument` error, exit 1 |

Operands after `--` are always file names, so `tee -- -x` creates a file named `-x`.

### Behavior

- **Files open before any input arrives**, so `true | tee out.txt` still truncates `out.txt`.
- **Streaming**: each record is written as it arrives and then passed on. A fast burst of records is buffered for up to 50 ms before it reaches the file.
- **Exact bytes**: a record without a trailing newline (`printf x`, `echo -n`) is written without one, so `printf x | tee f` produces a 1-byte file.
- **Device names**: `/dev/null` discards, `/dev/stdout` and `/dev/stderr` write tee's own streams, `/dev/fd/N` writes descriptor N. No file is created for any of them.
- **Errors**: a file that cannot be opened is reported (`tee: nodir/x: No such file or directory`) and the other files are still written. The message names the file as typed, and `tee` exits 1, as GNU does.

### Object behavior

`tee` writes each object's `BashText` to the files and passes the **original typed objects** downstream.

```powershell
$results = ls -la | tee listing.txt | grep '.ps1'
$results[0].Name             # PsBash.psm1
$results[0].SizeBytes        # 141234
```

`listing.txt` holds the full `ls -la` text; `grep` receives `LsEntry` objects and matches against their `BashText`.

### Examples

```bash
echo one | tee -a deploy.log > /dev/null
echo two | tee -a deploy.log > /dev/null
cat deploy.log
```

```text
one
two
```

```bash
# Save an intermediate stage while the pipeline continues
cat data.csv | grep -v '^#' | tee filtered.csv | wc -l
```

```bash
echo 'build started' | tee build.log backup/build.log
```

## xargs

Build and run commands from pipeline input. Input is split into arguments, and the arguments are appended to the command.

### Syntax

```text
xargs [OPTION]... [COMMAND [INITIAL-ARGS]...]
```

Options end at the first operand: everything after the command name belongs to the command, so `xargs grep -il foo` passes `-il` to grep.

### Flags

| Flag | Description |
|------|-------------|
| `-0`, `--null` | Items are separated by NUL |
| `-d DELIM`, `--delimiter=DELIM` | Items are separated by DELIM (`\n`, `\t`, `\r`, `\0`, `\\` escapes allowed) |
| `-I REPLACE` | Run once per input line, replacing REPLACE in the arguments with the line |
| `-i[REPLACE]` | Obsolete form of `-I`; `REPLACE` defaults to `{}` |
| `-n N` | At most N arguments per command |
| `-L N` | Treated as `-n N` (see differences) |
| `-r`, `--no-run-if-empty` | Do not run the command when there is no input |
| `-t`, `--verbose` | Print each command line to stderr before running it |
| `-p`, `--interactive` | There is no terminal to confirm on, so nothing runs: `xargs: failed to open /dev/tty for reading`, exit 1 |
| `-P N`, `--max-procs=N` | Accepted; commands run one at a time. N must be a number that is not negative (`xargs: invalid number "x" for -P option`, exit 1) |

The long forms `--max-args` (`-n`), `--max-lines` (`-L`), `--replace` (`-I`), `--delimiter`, and `--max-procs` take their value after `=` or as the next word.

### Input handling

By default the input is split on blanks and newlines, as in GNU xargs; single quotes, double quotes, and backslashes keep blanks inside one argument. With `-I`/`-i`, each input line is one argument: leading blanks are stripped and quotes and backslashes are still applied. With `-0` or `-d`, items are split only on the delimiter.

Typed pipeline objects contribute their `BashText`.

With no command, xargs runs `echo`. A bash command name that ps-bash implements (`rm`, `grep`, `basename`, ...) runs the ps-bash version; other names resolve to PowerShell commands or programs on `PATH`. xargs can run `true` and `false` on every platform: `echo a | xargs false` exits 123.

### Exit status

| Status | Meaning |
|--------|---------|
| `0` | Every command succeeded |
| `123` | A command exited 1-125 |
| `124` | A command exited 255 (xargs stops) |
| `126` | The command could not be run (xargs stops) |
| `127` | The command was not found (xargs stops) |

### Differences from GNU

- `-L N` counts input items, not input lines.
- Input comes from the pipeline only.
- `-s`, `-x`, `-E`, `-a`, and `--process-slot-var` are not implemented. An unrecognized option is taken as the command name.

### Examples

```bash
printf 'a b\nc\n"d e" f\n' | xargs echo
```

```text
a b c d e f
```

```bash
printf 'a\nb\nc\nd\n' | xargs -n 2 echo pair:
```

```text
pair: a b
pair: c d
```

```bash
printf 'a\nb x\n' | xargs -I {} echo 'Hello {}!'
```

```text
Hello a!
Hello b x!
```

```bash
find . -name '*.tmp' -print0 | xargs -0 rm -f
```

## less and more

Pagers. When the output is not an interactive terminal (a pipe, a redirect, a script, the Bash tool), both pass their input through unchanged, so `cmd | less` in a script behaves like `cmd`.

### Syntax

```text
less [OPTION]... [FILE]...
more [OPTION]... [FILE]...
```

### less

- **Non-interactive**: pipeline objects pass through as they are; file operands are emitted line by line. A missing file prints `less: FILE: No such file or directory` and exits 1.
- **Interactive** (interactive shell, terminal on stdin and stdout): runs the native `less` found on `PATH` with your arguments (`-N`, `-i`, `-S`, and any other flag). Pipeline input is written to a temporary file first. With no native `less` installed, the input is printed instead.

### more

- Pipeline objects and file lines are emitted without paging. Dash and `+NUM` arguments are accepted and ignored.
- There is no interactive paging loop; `more` prints everything in both modes.

### Differences from GNU

- GNU `more` writing to a non-terminal prints a `::::::::::::::` header with the file name before each file; ps-bash prints only the content.
- `less nofile` exits 1; GNU `less` exits 0.

### Examples

```bash
printf 'a\nb\n' | less | wc -l     # 2: nothing is paged in a pipe
```

```bash
git log | less -S                  # in an interactive shell: native less
```

## browse

`browse` is an interactive, object-aware table for pipeline output (`ls -la | browse`, `ps aux | browse`), with a scriptable `--list` mode. Without a terminal it prints a line-mode list instead of blocking. See [Interactive TUIs from a .psm1](/ps-bash/guides/interactive-tui/) for keys, flags, adapters, and the safety model.
