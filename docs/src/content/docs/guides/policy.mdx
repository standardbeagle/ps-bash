ps-bash often runs shell text nobody reviewed: commands an LLM agent wrote, `package.json`
scripts, CI steps. This page lists what ps-bash itself guards against, what it does not, and
what to use for the rest.

<Aside type="caution" title="ps-bash is not a sandbox">
ps-bash has no policy engine: no allow or deny lists for commands, arguments, paths or network
access. A script runs with the full rights of the user who started it. Put any isolation you need
around ps-bash, at the OS level.
</Aside>

---

## What ps-bash does

### A child sees exported variables only

As in bash, a program started from a script gets only the variables that were inherited or
exported (`export`, `declare -x`, `set -a`, `NAME=v cmd`). A plain `TOKEN=x` assignment stays in
the shell:

```bash
TOKEN=secret
sh -c 'echo "[$TOKEN]"'     # []
env | grep -c '^TOKEN='     # 0
```

One gap remains: a native program that PowerShell starts directly (a plain `prog args` without
`2>&1`, and any `.cmd` or `.bat`) inherits the whole process environment, unexported variables
included. Programs started with a stderr merge, and every nested shell, are not affected.
Variables the shell inherited at startup are exported, so a secret in the agent's own
environment reaches every child, as it would in bash.

### PowerShell aliases do nothing

A ps-bash runspace keeps only its own `Invoke-Bash*` aliases. Words such as `iex`, `r`, `write`,
`start`, `del` or `%` are not PowerShell aliases there: each resolves to a shell function, a
program on `PATH`, or "command not found" (exit 127), as in bash. So `iex '…'` does not evaluate
PowerShell.

### rm refuses the root and your home directory

`rm -r` on `/` or a drive root is refused with GNU's `--preserve-root` message. Unlike GNU,
`--no-preserve-root` does not remove that guard: `rm` refuses the drive root, `/` and your home
directory itself with `rm: refusing to remove '…': protected path`. Only the directory itself is
protected. `rm -rf ~/*` deletes everything in your home directory.

### Bounds on a runaway command

| Control | Effect |
|---------|--------|
| `--timeout N` / `PSBASH_TIMEOUT=N` | Kill a command that prints nothing for N seconds (exit 124) |
| `PSBASH_HOST_MAX_MB` | Stop a command whose host passes the memory limit (exit 137) |
| `PSBASH_PER_INVOCATION=1` | Give each command its own host that exits with it, so nothing stays running |

The host also survives hostile input: deep nesting and huge brace expansions are parse errors, and
a command that ignores Ctrl+C is ended with its host. See
[The Host Daemon](/ps-bash/reference/host-daemon/#a-command-cannot-take-the-host-down).

### AI assist is off by default

The interactive shell's AI command assist sends your buffer to an external CLI. It stays off until
you set `PSBASH_AI_ENABLE=1`, and `PSBASH_AI_DISABLE=1` overrides that. See
[The Interactive Shell](/ps-bash/guides/interactive-shell/).

## What ps-bash does not do

- **No command, argument or path restrictions.** Any program on `PATH` can run. A command word that
  names a PowerShell cmdlet, such as `Remove-Item` or `Invoke-Expression`, runs that cmdlet.
- **No network control.** `curl`, `wget` and any native program reach the network as the user can.
- **No filtering of inherited secrets.** Variables in the environment ps-bash started with are
  exported to every child.
- **No isolation of in-process PowerShell.** A `.ps1` file, or a cmdlet called by name, runs with
  the host's full rights and is outside the host's crash guards.

## What to use instead

| Need | Use |
|------|-----|
| Keep a job inside its workspace | A container or VM with only the workspace mounted |
| Keep secrets from an agent or script | Start it with a scrubbed environment; do not export secrets into its shell |
| Limit what files a process can touch | A restricted user account, or AppArmor / SELinux on Linux |
| Limit CPU, memory and process count | Windows Job Objects, cgroups, or the container runtime |
| Limit network access | A firewall rule or the container's network policy |
| Review agent commands | Your agent's own permission prompts or allow lists |
