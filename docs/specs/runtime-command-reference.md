# Command Reference

> Part of the [Runtime Functions Specification](./runtime-functions.md). One row per emulated command: the `Invoke-Bash*` command, key flags, arg-parsing strategy, and whether it accepts pipeline / file input. Binary cmdlets are documented in detail in [Migrated Binary Cmdlets](./runtime-migrated-cmdlets.md).
>
> **Every command here is a binary cmdlet in `PsBash.Cmdlets.dll` unless its row says otherwise.** An "Arg Parsing" cell reading `Manual loop` / `Positional` / `ConvertFrom-BashArgs` names the strategy *inside* the cmdlet, not a psm1 function. The only leaf commands still implemented in `PsBash.psm1` are the job-control set (`wait`, `jobs`, `fg`, `bg`, and the internal `Invoke-BashBackground`), which needs runspace-pool state; the psm1 functions `Invoke-BashSed` / `Invoke-BashGrep` are literal-argument proxies in front of the real cmdlets (direct PowerShell calls only). See [runtime-functions.md](./runtime-functions.md#where-a-command-actually-lives-refactor-2-is-essentially-complete).
>
> **Common-parameter prefix-capture audit (R22).** A repeated *value* parameter (e.g. `string[] E`) is rejected by the PowerShell binder with "parameter 'E' is specified more than once" before the cmdlet body runs, and a single-dash bundle whose letters prefix-match a common parameter (`-ve` → `-Verbose`) is taken by the binder instead of reaching the cmdlet. `grep` and `sed` are on `OrderedArgCommands` (from the transpiler every flag reaches their cmdlet verbatim, single-quoted, in order) and keep an `Invoke-BashGrep` / `Invoke-BashSed` psm1 PROXY only for direct PowerShell calls: it hands every argument over as a literal string (`ConvertTo-BashLiteralArgs`), so nothing reaches the binder, and interprets no flag. The audit of the other migrated cmdlets found one same-class defect: **`awk` declared `-v VAR=VAL` as `string[] V`, so `awk -v a=1 -v b=2` crashed identically** — fixed without a proxy: awk is on `PsEmitter.OrderedArgCommands`, so from the transpiler every flag reaches `Arguments` single-quoted and the cmdlet's own scan handles repeated `-v` (and stops option parsing at the program text). The declared `V` remains for a SINGLE direct `Invoke-BashAwk -v a=1 …`; a REPEATED bare `-v` typed directly at PowerShell still hits the binder — quote the flags (`'-v' a=1 '-v' b=2`). Cmdlets whose bundles must reach `Arguments` already declare decoy switches or rely on the emitter's single-quoting (`find` is on `OrderedArgCommands`, so its infix `-o`/`-a` arrive verbatim); no other value-bearing single-letter parameter repeats in practice.
