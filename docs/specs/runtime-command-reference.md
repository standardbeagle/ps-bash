# Command Reference

> Part of the [Runtime Functions Specification](./runtime-functions.md). One row per emulated command: the `Invoke-Bash*` command, key flags, arg-parsing strategy, and whether it accepts pipeline / file input. Binary cmdlets are documented in detail in [Migrated Binary Cmdlets](./runtime-migrated-cmdlets.md).
>
> **Every command here is a binary cmdlet in `PsBash.Cmdlets.dll` unless its row says otherwise.** An "Arg Parsing" cell reading `Manual loop` / `Positional` / `ConvertFrom-BashArgs` names the strategy *inside* the cmdlet, not a psm1 function. The only leaf commands still implemented in `PsBash.psm1` are the job-control set (`wait`, `jobs`, `fg`, `bg`, and the internal `Invoke-BashBackground`), which needs runspace-pool state; `sed`'s psm1 function is a `-e`-bundling proxy in front of the real cmdlet. See [runtime-functions.md](./runtime-functions.md#where-a-command-actually-lives-refactor-2-is-essentially-complete).
>
> **Common-parameter prefix-capture audit (R22).** A repeated *value* parameter (e.g. `string[] E`) is rejected by the PowerShell binder with "parameter 'E' is specified more than once" before the cmdlet body runs, and a single-dash bundle whose letters prefix-match a common parameter (`-ve` → `-Verbose`) is taken by the binder instead of reaching the cmdlet. `grep` is fixed by an `Invoke-BashGrep` psm1 proxy (same pattern as `sed`). The audit of the other migrated cmdlets found one remaining same-class defect: **`awk` declares `-v VAR=VAL` as `string[] V`, so `awk -v a=1 -v b=2` crashes identically** — it has no proxy yet and needs the same treatment (tracked out of R22's file scope). Cmdlets whose bundles must reach `Arguments` already declare decoy switches or rely on the emitter's force-quoting (`find` force-quotes infix `-o`/`-a`); no other value-bearing single-letter parameter repeats in practice.

native `ffmpeg` stay un-aliased and fully interactive; `psav raw -- <args>` reaches ffmpeg
