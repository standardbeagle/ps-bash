# POSIX ERE: `[[ s =~ re ]]`

`[[ s =~ WORD ]]` is glibc POSIX ERE, run by ONE primitive: `BashEre` (`src/PsBash.Transpiler/Parser/BashEre*.cs`).
Never .NET regex (guard `Core.Tests/EreNoDotNetRegexGuardTests`). Oracle: bash 5.2.21, glibc 2.39, `C.UTF-8`.

## Invariant

bash builds regcomp's text from the word with `quote_string_for_globbing(QGLOB_REGEXP|QGLOB_CTLESC)`, then calls
`regcomp(REG_EXTENDED [|REG_ICASE under shopt -s nocasematch])` and `regexec`. ps-bash does the same, in this order:

1. **The word** (`PsEmitter.BuildEreWord` → `PsBuild.EreTest`). A quoted character (`'…'`, `"…"`, `$'…'`, an
   unquoted `\c`, a tilde's expansion) is marked with CTLESC (`BashPatternMatch.EreQuote`). Unquoted text and the
   value of an unquoted expansion (`re='a.b'; [[ $s =~ $re ]]`) stay regex text (`EreRaw` doubles a CTLESC in it).
2. **`BashEre.WordToRegex`**. This is a port of pathexp.c. A marked ERE special (`. [ \ ( ) * + ? { | ^ $`) becomes
   `\c`, and any other marked character becomes itself. So the word `\d` is the regex `d`, `a"."c` is `a\.c`, and
   `\<` is `<`. A marked character inside `[…]` is plain. An unclosed `[` is rescanned as text.
3. **`BashEre.Match(regex, icase, subject)`**. This is a port of glibc regcomp, matched by a non-backtracking
   simulation:
   - **Leftmost-longest.** `(a|ab)` on `ab` is `ab`. `a*?` is `a*` then `?`, not lazy.
   - **glibc's captures.** The ported code is `set_regs`/`proceed_next_node`/`update_regs`. `(a|ab)(c|bcd)(d*)` on
     `abcd` gives `a,bcd,""`. `(a*)*` on `b` gives `""`. A group that took no part is `""`.
   - **Newlines are ordinary characters.** `.` and `[^x]` match a newline. `^`, `$`, `` \` `` and `\'` hold only at
     the true start and end of the subject.
   - **No Perl syntax.** `(?:`, `(?=`, `(?b` are REG_BADRPT. `\d` is `d`, `\K` is `K`, `\x62` is `x62`.
   - **GNU escapes**, which glibc accepts in a regex held in a variable: `\w \W \s \S \b \B \< \> \` \'`.
     Back-references `\1`–`\9` also work there.
   - **Code points, not bytes or UTF-16 units.** `é` is one `.`.
   - **Classes are glibc's C.UTF-8 tables**, in `BashEreClasses.Table.cs`, generated by
     `scripts/ere-classes-gen.py` from an oracle dump. For example, `٣` is `alnum` but not `digit`, and `€` is
     `punct`. `[a-z]` is a code-point range. `[[=e=]]` is just `e`. A multi-character `[[.x.]]` or `[[=x=]]` is an
     error.
   - **icase.** Both sides are folded with glibc's `towupper`. An escaped ASCII pattern character is not folded, so
     under nocasematch `\d` matches neither `d` nor `D`. `[:upper:]` and `[:lower:]` become `[:alpha:]`.
   - Every REG_* error (BADRPT, EBRACE, BADBR, EPAREN, EBRACK, ERANGE, ECTYPE, ECOLLATE, ESUBREG, EESCAPE) is
     status 2.

## BASH_REMATCH

| Outcome | Status | BASH_REMATCH |
|---|---|---|
| Match | 0 | The whole match, then every group (`""` for a group that took no part) |
| No match | 1 | An **empty array**: `${#BASH_REMATCH[@]}` is 0, and `"${BASH_REMATCH[@]}"` is no words |
| regcomp error | 2 | **Unchanged**. bash prints no message |

`PsBuild.EreTest` sets `$global:BASH_REMATCH = $result.Groups` for statuses 0 and 1. For status 2 it sets
`__BashTestBad`, which the test wrapper turns into status 2. It used to assign `$null` on no match, so
`"${BASH_REMATCH[@]}"` failed with "Object reference not set".

## Bounds (host-lifecycle-contract.md §No input may take the host down)

The engine runs inside the shared host. A regex past any of these bounds is status 2 (ps-bash only; see
intentional-differences.md). None of them can hang or crash the host.

| Bound | Value | Where it is enforced |
|---|---|---|
| Nesting | 1000 groups deep | `NestingGuard` in `ParseSubExp` |
| Tree size | 400,000 nodes | REG_ESPACE; glibc's own limit is `RE_DUP_MAX` = 32767 per `{n}` |
| Matcher work | 200M steps | Applies per match |
| Capture bitsets | 4M words | Applies per match |

Without back-references the matcher is O(n·m) in time, for subject length n and m NFA nodes. `^(a|aa)*$` and
`(x+x+)+y` over thousands of characters take milliseconds. Back-references are NP-hard in general; their
per-start search is bounded by the same work budget.

Compiled programs are cached, 512 entries keyed by (regex, icase).

## Other ERE consumers (NOT routed through BashEre yet)

All of these still translate to .NET regex. They are candidates for the same primitive. Each has its own dialect
details: BRE, awk's dynamic regex, and GNU find's `-regextype`.

| Command | Where it is implemented | Dialect |
|---|---|---|
| `grep -E` / `-G` | `InvokeBashGrepCommand.cs`, using `BashRuntime.TranslateBre` / `TranslatePosixClasses` | GNU ERE / BRE |
| `sed -E` / `-r` / BRE | `InvokeBashSedCommand.cs` | GNU ERE / BRE |
| `awk` `~`, `match()`, `sub()`, `split()` | `AwkMachine.cs`, using `TranslatePosixClasses` | POSIX ERE (awk) |
| `find -regex` / `-iregex` | `FindRegexDialect.cs` | emacs default, plus `-regextype` |
| `expr STR : RE` | `ExprEvaluator.cs`, using `TranslateBre` | BRE |

Two related commands are not POSIX ERE: `rg` (`InvokeBashRgCommand.cs`) uses Rust regex syntax, and `jq` `test()`
(`JqRegex.cs`) uses Oniguruma.
