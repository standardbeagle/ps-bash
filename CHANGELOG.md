# PsBash Release Notes Archive

Full, detailed release notes for every version. The module manifest
(`src/PsBash.Module/PsBash.psd1`) carries only condensed one-line summaries of
the most recent releases to stay under the PSGallery ReleaseNotes size cap; this
file is the complete history. See also the GitHub releases:
https://github.com/standardbeagle/ps-bash/releases

## v0.15.0

Bash-compatibility release, with behavior checked against bash 5.2 and GNU coreutils. Expected-failure (XFAIL) marks in the bash spec suite (`spec/`) drop from 140 to 79: the Oils suite goes from 127 to 78 and the differential cases from 13 to 1. Of the 79 that remain, 58 are Windows platform limits (drive-letter paths, no `/usr/bin`, case-insensitive names). Open items are in `docs/known-issues.md`.

**Breaking changes.** (1) Paths a script sees use forward slashes on Windows: `$PWD`, `$OLDPWD`, `~`, `$HOME`, `pwd`, `mktemp`, `realpath`, `readlink`, `type`/`which`/`command -v`, `$0`, `BASH_SOURCE` and the `<(cmd)` word print `C:/Users/x` (was `C:\Users\x`). `${PWD##*/}`, `IFS=/ read` and `for f in $dir/*` now work; a script that matched or split on `\` must use `/`. Input still accepts `C:\x`, `C:/x`, `/c/x` and `/mnt/c/x`; `PATH` keeps its `;` form; a native program's own output is not rewritten. (2) A bash script no longer resolves PowerShell's built-in aliases (about 135). `gci`, `iex`, `r` and `write` behave as in bash: a function or PATH program of that name runs, otherwise "command not found" (127). `where` runs `where.exe`. Use the full cmdlet name (`Get-ChildItem`). Importing the module into your own pwsh leaves its aliases alone. (3) A nested shell, and a program started with `2>&1`, `&>` or `|&`, sees exported variables only: `x=1; sh -c 'echo $x'` prints an empty line, and `env`, `printenv` and `compgen -e` list exported names. Add `export`. A program started plainly (`prog args`, also through `env`, `command`, `xargs` or `time`) still inherits every shell variable. (4) Background job output streams as the job runs instead of appearing at `wait`, and an in-process job reads its own copy of the shell's variables, taken at the `&` (`x=a; { sleep .3; echo $x; } & x=b; wait` prints `a`). (5) `set -e` ends a pipe stage at its failing command (`{ echo one; false; echo two; } | cat` prints `one`), and `exit` in a function called from a pipe stage, `( )` or `$( )` ends only that subshell. (6) Stopping a command (Ctrl+C, `timeout`, a pipeline stop) ends its whole process tree, including a child a script left running with `&`; a `setsid` child survives. A program started plainly (`prog args`) is still stopped alone, without its children. (7) `readlink FILE` on a non-link prints nothing with status 1 and `realpath nosuch/x` fails, as GNU does; both printed a path before. (8) Commands no longer re-glob an operand the shell already expanded: `head 'two-*'` names a file called `two-*`.

**Signals and background jobs.** A signal sent to a ps-bash shell's pid reaches the script: `kill -USR1 $$` from a nested shell runs the enclosing script's trap at its next statement, or ends it with 128+N when there is no trap. It was refused before. Jobs print in launch order (`echo a & echo b &` prints `a` first), start in runspaces that are already open (the first statement runs about 13 ms after the `&`; a private pool cost 437-687 ms), hold bounded memory, and a job's `sleep` counts from its `&`. `kill -l` prints bash's table including the real-time signals 34-64, and `kill -34 pid` sends 34 (it sent TERM). A loop variable no longer shadows an assignment inside a job (`{ i=9; echo $i; } &` in a loop printed the loop value), a job that reads stdin alongside the foreground no longer fails at end of input, and a trap set only through `eval` text runs when its signal arrives.

**Pipelines and stdin.** Line tools join a piece without its newline into the next line: `{ printf a; printf 'b\n'; } | sed s/x/y/` prints `ab`; it printed `a` and `b` on two lines. This affected 25 commands, among them sed, awk, grep, sort, head, cut and xargs. A record keeps its trailing empty lines (`printf 'a\n\n' | grep -c ''` prints 2). `producer | while read l` reads each line as the producer writes it, so `yes | while read l; do break; done` ends. A `read`, `cat` or `head` in a read loop's body sees the pipe, as does a reader behind a function, `source` or `eval`; a redirected loop (`| while read l; ...; done > f`) no longer writes an empty file. Under `pipefail`, a pipeline after `&&` or `||` parses (`a && b | c` was a PowerShell parse error for the whole script). An assignment statement sets `PIPESTATUS`.

**Control flow and variables.** `break` and `continue` stop at subshell boundaries; `! f` honors a `set -e` turned on inside `f`; `shopt -s inherit_errexit` works; a bad substitution discards only the rest of its input line. A callee's `local q` is no longer hidden by the caller's `for q` loop variable. New or fixed: `BASH_LINENO`, a per-subshell `$BASHPID`, `hash` with bash's table (`-t -d -r -p -l`), `export SHELLOPTS` reaching a child shell, `let` with the full arithmetic grammar, `${PS1@P}`, `printf -v 'm[$k]'`, namerefs forwarded through `"$@"`, `{a,}` as one word, `{fd}>file` on a simple command, `set -o posix` special-builtin rules, `--rcfile`, and `-e -u -x -v -o -O` on a script file. A positional index too large for an integer (`${99999999999999999999}`) is unset, as in bash, instead of failing the transpile. "command not found" carries bash's `NAME: line N:` prefix, and a slash path that cannot run reports the exec error (126 "Is a directory", 127 "No such file or directory").

**Processes.** A nested `bash -c`, `sh -c` or `bash script.sh` streams its output and input and is no longer killed after `PSBASH_TIMEOUT`. awk `system()` and pipes, `rg`, `sed e` and `git` run with no time limit and stop on Ctrl+C. A child under `2>&1`, `|&` or `&>` gets one pipe for both streams, so its write order is kept. `command FILE` and `nohup FILE` run a `#!` script through its interpreter (on Windows `command ./script` opened the "Open with" dialog). A function, a `#!` script and a job's program get their arguments as typed (`--`, `-x:y`, `perl -e '...' &`). A `#!` line naming a missing interpreter is 127. A child that closes its stdout and stderr and keeps running reports its own exit status (it was reported as 124 and killed after 2 s), and a fast child's unread output is capped at about one pipe buffer, which holds the child back as a full pipe does. A stop also ends a command that awk's `close()` is waiting for.

**Files and devices.** A `/dev/*` name is never opened as a file (`echo {v}>/dev/stdout` wrote `C:\dev\stdout`). `> file` writes as output is produced, so `tail -f log` follows a running script. `readlink` and `realpath` canonicalize through one port of gnulib's walk and gain `-n`, `-z`, `-s`, `-L`, `-q` and a real `-m`. A file named twice keeps both spellings (`wc ./f f`), diagnostics name the operand as typed, `wc - f` counts the pipeline, and usage errors print the tool's `Try 'cmd --help'` line. `cd` keeps the logical path and `pwd -P` resolves every link. `base64` and `od` stream, so `base64 /dev/urandom | head -c 32` and `od -v /dev/zero | head -1` end. Writes to an `exec 3>f` descriptor reach the file when each command ends, so a program run next (`stat -c %s f`) sees all of them.

**Builtins and shell variables.** A builtin named at run time runs: `c=eval; $c 'echo x'`, `run() { "$@"; }; run eval ...` and `command NAME` gave 127 for `eval`, `.`, `set`, `exec`, `local`, `break` and `continue`. New builtins: `enable`, `caller`, `disown`, `bind`, `suspend`, `logout` and `help` (bash's synopsis and one-line description for 61 builtins; it ran PowerShell's `Get-Help`). The quoted word `pipefail` in a script no longer breaks the parse. `PPID`, `SHLVL`, `GROUPS`, `DIRSTACK`, `BASH_ALIASES`, `SRANDOM` and `BASH_SUBSHELL` are set, and `$IFS` has its default before it is assigned. An ERR trap set in a subshell or function fires, and a subshell, function or `$( )` starts without the caller's ERR trap unless `set -E`. `trap 'echo D' DEBUG; echo a` on one line runs the trap. A pipe stage stopped by a later stage keeps its own status (`nosuchcmd 2>&1 | head -1 >/dev/null` leaves 127 in `PIPESTATUS[0]`). An unquoted `${@:2:2}` or `${*: -1}` splits into words, operators work on the special parameters (`${!:+x}`, `${?:-q}`), and an associative key may hold blanks or quotes (`declare -A m=([x y]=1)`). `exec 5<>file` opens a read-write descriptor. `select` and `coproc` print `not supported by ps-bash` with status 2 and the script goes on; `select` was dropped silently. Number-shaped words keep their text: `f 1e5` passes `1e5` (it passed 100000), and `08` and `{-0,1}` are unchanged. A background job that signals itself (`{ kill -USR1 $BASHPID; } & wait $!`) ends with 128+N and the script goes on; the signal ended the whole script.

**Commands.** Two changes can break a script: `env NAME` runs NAME as a command, as GNU does (it printed the variable; use `printenv NAME`), and `mktemp app.XXXXXX` creates the file in the current directory (it went to the temp folder). `mktemp` follows GNU's rules: the X run is replaced in place, `$TMPDIR` is honored, and `-t`, `--tmpdir`, `--suffix`, `-u` and `-q` work. A signal that does not exist is refused: `kill -FOO`, `kill -99` and `kill --signal=FOO` print `invalid signal specification` (they sent TERM), and `timeout -s FOO` and `timeout --kill-after=x` exit 125. GNU long-option spellings work in `awk` (`--file=`, `--field-separator=`, `--assign=`) and `xargs` (`--max-procs=`, `--max-args=`, `--max-lines=`, `--delimiter=`, `--replace=`). `date` gains `-I[FMT]`/`--iso-8601`, `-R`/`--rfc-email`, `--rfc-3339` and `%:z`; these options were ignored before. `expr` follows GNU's precedence and chains, with `|`, `&` and parentheses: `expr 1 + 2 + 3` prints 6 (it printed 3). A `printf` conversion with no argument left keeps its width and prints 0 for a number. `tr -t` truncates SET1, and `-d` with `-s` runs in GNU's order. `env` exits 125, 126 and 127 as GNU does and takes `-0` and `-C DIR`; `env X=1 printenv X` prints `1`, and `xargs false` exits 123. `gzip -l` prints GNU's table, `-v` writes to stderr, a warning exits 2, files are named as typed, and `gunzip FILE` finds `FILE.gz`. `tee` exits 1 when a file cannot be opened. `shuf` reports a missing file. `nl` pads a line it does not number. `tac -s` keeps each separator attached. `mkdir -pv`, `rmdir -pv` and `install -v` name each directory as typed, and `rmdir -p a/b` no longer removes empty directories above `a`. `uname` reports the host kernel on Linux and macOS (`Linux`, `Darwin`); Windows keeps `MINGW64_NT`. `id` for an unknown user fails. `ping` exits 1 when no probe is answered and 2 for a host that does not resolve. `tput` with an unknown capability exits 4. The coreutils commands share one `missing operand` error, and `dirname` with no operand exits 1. `rg` prints `/` in the paths it finds on Windows. `wc` pads its columns as GNU does: `echo hi | wc` prints `      1       1       3`.

**Unicode quote and dash marks.** PowerShell ends a string at U+2018-U+201E and reads a word starting with U+2013-U+2015 as a parameter. `echo it’s` was a parse error that failed the whole script, and `echo –n x` ran `echo -n`. All emitted PowerShell quoting now goes through one builder that escapes these marks.

**macOS and Linux arm64.** Scripts on macOS no longer die with exit 138 and no output: the .NET runtime uses SIGUSR1 there, so ps-bash leaves it alone. Signal numbers, wait statuses, `struct stat`, process info and the terminal `ioctl` come from one platform layer; on arm64 the runtime-directory owner check had read the uid as the mode. Setuid programs (`ps`, `sudo`, `ping`) start on macOS, and system tools are found in `/bin` as well as `/usr/bin` (Alpine).

**Host.** A launcher that finds every executor slot busy for 2 s runs its command on a private host instead of waiting (`PSBASH_EXEC_OVERFLOW_MS`, `PSBASH_EXEC_OVERFLOW_MAX`; at most 2 such hosts per session by default, after which it waits); six long builds used to make every further `bash -c` wait minutes. A launcher killed mid-spawn no longer leaves a second shared host behind. A socket file is removed only when nothing listens on it. Module re-extraction never rewrites a file a running host may have mapped (the rewrite crashed that host with SIGBUS on macOS and Linux). A host start that is slow but alive gets more time instead of failing with exit 125.

**Performance.** 100 subshells in a busy directory on Linux: 10.6 s to 0.3 s. 10,000 `a+=(x)` appends: 10.7 s to 1.4 s. A nested `bash -c` connects to its host in about 120 ms (was about 360 ms); the whole nested shell still takes about 1 s. Cold host start: 1,090 ms to 1,000 ms.

## v0.14.0

Remote sessions. New: ps-bash session attach NAME gives a reattachable terminal (tmux-style) - a detached broker owns a PTY and the interactive shell, so the shell and its screen outlive the client; Ctrl-] d detaches, a new client gets the last 1 MiB of output replayed, several clients can attach (--read-only to watch), and session stop ends it. Remote use is ssh -t host ps-bash session attach NAME. Works on Linux, macOS and Windows (ConPTY); the wire protocol is documented in docs/sessions.md. Named sessions (PSBASH_SESSION=NAME) are now stateful by default: variables, cd and functions persist between commands in one pinned runspace (--stateless restores a fresh runspace per command); session list shows each mode. Changed: the Windows named-pipe transport is removed; AF_UNIX sockets are the only transport (a socket path over the OS limit now fails with a message naming TMPDIR). Fix: a shell started under a Windows pseudoconsole no longer inherits the parent redirected stdio (it read EOF and exited with no prompt), so PSBASH_PTY=1 works when ps-bash is launched from a pipe-driven parent.

## v0.10.22

Arithmetic, compact-output, and host reliability fixes. Arithmetic substitution (`$((...))`), arithmetic commands (`((...))`), and C-style `for ((...))` clauses now use one typed parser and runtime evaluator, preserving Bash precedence and side effects across all three forms. This also fixes nested parentheses and positional/special parameters such as `$0`, `$1`, `${10}`, `$#`, and `$?` (including Bash's `$10` versus `${10}` distinction), while malformed arithmetic consistently reports a parse error. Robustness & security batch from a four-subsystem code review (37 findings). Transpiler: expanding-heredoc command substitutions $(...) and backticks are now transpiled instead of executed as raw PowerShell (a quoting-seam code-execution leak), with backslash escapes honoured; quote-aware ${...} boundary scanning; brace-expansion items escaped via PsBuild; subshell input redirects (cmd) < file; and a class of parser crashes now emits a clean positioned error instead (lone here-string quote, out-of-range fd, for $i, empty redirect target, ${10000000000}, oversized brace tuples). BashArith hex/octal literals wrap at 64 bits instead of throwing. Cmdlets: the entire PowerShell common-parameter binder-collision cluster is resolved — every colliding short flag (cp/mv/rm -i, cat -A/-v, column -o/-c, tee -p, tree -p/-C, split -e/-C, strings -a/-e, grep -d/-D, sort -i, head/tail -v, du -P, uniq -w, readlink -e/-v, mktemp -p) now binds a decoy parameter so it no longer crashes the binder or silently drops, with the collision guard extended to catch the class mechanically; column -s with an empty separator no longer splits per character; tail -f withholds a partial final line until its newline arrives. Host/shell: Ctrl-C no longer races the prompt-loop token dispose into a process crash; Tab completion is deadline-bounded so it never hangs; the alias table is concurrency-safe; completion columns use display width; POSIX cwd tracking, scrollback preservation on a clean non-zero exit, and frecency-store disposal on the connection-lost path are fixed; ps-bash -c cmd --version now runs the command instead of printing the banner. Core/IPC: the stale-artifact reaper unlink race and a ModuleExtractor winner mis-handling are closed; the post-EXIT read is deadline-bounded; a persistent spawn-lock permission error degrades to an unguarded spawn instead of a 20s stall; compact output flushes a partial digest on a transport reset; a CommandNameCache lost-wakeup is fixed.

## v0.10.12

Per-session host daemon (multi-agent contention fix) + a Tab-completion fix. The ps-bash-host daemon is now keyed per (user, session) instead of one shared daemon per user. Independent shells / agents each get their own warm daemon — the session token is the PSBASH_SESSION env var, or when unset the launcher's parent process id — so N concurrent callers no longer pile onto a single host and starve its warm runspace pool. That contention was the cause of multi-second-to-multi-minute stalls when many ps-bash -c invocations ran at once (e.g. several Claude Code agents sharing one machine, each command discarding its runspace and forcing the shared pool to cold-warm under CPU saturation). Repeated invocations from one shell still share a hot daemon (warm reuse ~0.2s); only independent sessions diverge, and each session's daemon is reaped by idle-shutdown. When no session token is available the historical per-user endpoint is used (back-compat). Tab completion: a command-position token containing a slash or ~ (./script, ../bin/x, dir/x, ~/x) now does filename completion over directories AND files — so ./sc<Tab> offers ./scripts/ — matching bash, instead of returning nothing (it previously scanned only files in the cwd and never directories).

## v0.10.9

Interactive shell features and runtime bug fixes. (1) cd - returns to the previous directory ($OLDPWD) and echoes it like bash; every successful cd now records $OLDPWD, and cd - with no prior directory reports "cd: OLDPWD not set" instead of failing on an empty path. (2) Bash history expansion in the interactive shell: !! (previous command), !n / !-n (by session index), !str / !?str? (prefix / substring search), the !$ / !^ / !* word designators and :n suffixes, and ^old^new quick substitution; expansion is suppressed inside single quotes and after a backslash, leaving the ! negation operator untouched. (3) ln -sf no longer destroys a populated directory tree: when the link name is a real directory the link is created inside it (basename of the target) and -f only removes a file or symlink, matching GNU ln (the old code ran a recursive delete). (4) awk file-operand mode: awk '{...}' file.txt now reads the named file(s) instead of silently dropping the operand and reading nothing. (5) kill fixes: named-signal short forms (kill -KILL / -TERM / -SIGTERM pid) are honored, and the pid loop no longer collides with the read-only $PID automatic variable, which silently broke every kill. (6) Stale-host fix: the daemon build identity now folds the host binary file stamp, so a recompiled host (same version, new code) replaces a running daemon instead of being silently reused. (7) Docs: new Interactive Shell guide and a Windows coreutils (uutils) comparison.

## v0.10.8

Robustness and interactive performance. (1) Interactive typing latency: keystrokes echo before the history/flag prediction runs, and prediction is fully async/debounced so a busy or IO-bound system never stalls input (set PSBASH_NO_PREDICT to disable it); the prompt is now drawn before the runspace finishes starting (startup type-ahead). (2) Hash-based transpile cache: startup .sh scripts transpile once and are cached on disk by content hash, with an in-memory LRU for repeated longer commands. (3) Bash-tool dogfood fixes: if/while/until conditions now test the command EXIT CODE rather than its output, so "if grep -q ..." and "if ! cmd" branch correctly; [ ... ] / test are silent (no stray True/False on stdout); every command resets the exit code on success (a trailing pwd no longer reports a stale 127); piping into "while read" now feeds the loop body; /dev/null as a file operand is an empty file instead of a crash; "cp -rf" bundled short flags are honored; and rm -rf / cp / mv / find -delete clear the read-only attribute so they no longer fail partway on Windows .git and node_modules trees. (4) grep gained --include / --exclude / --exclude-dir, -L/--files-without-match, -x/--line-regexp, -s/--no-messages, and -P/--perl-regexp. (5) "<cmd> --version" now identifies ps-bash across all commands. (6) Internals: emitted PowerShell is built through one shared builder and destructive filesystem operations through shared OS helpers, eliminating a class of one-off seam bugs (e.g. a negated-condition that took the wrong branch).
